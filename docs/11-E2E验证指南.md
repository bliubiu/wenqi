# 文气（WenQi）E2E 验证指南

> 本指南是 [08-测试策略文档.md](./08-测试策略文档.md) §4.6「E2E 测试」的执行落地说明，描述如何用一条命令完成**可幂等重跑**的全量端到端验证。

---

## 1. 目的与范围

- **目的**：在本地开发环境一键验证项目关键业务闭环全部可用，且任意次数重复运行结果稳定（幂等），作为发布前的准入检查。
- **范围**：Playwright 驱动的真实浏览器端到端测试（3 个执行项目、5 条业务用例），覆盖桌面端、移动端与无 WebGL 降级三类环境。
- **不包含**：单元测试（用 `bun run test:run`）、类型检查（用 `bunx tsc --noEmit`）、性能测试。

## 2. 快速开始

```bash
bun run verify:e2e
```

执行结束退出码为 `0` 表示全部通过；非 `0` 表示存在失败，报告见 `e2e-report/verify-<时间戳>.md`。

参数可透传给 `playwright test`（注意 `--` 分隔）：

```bash
bun run verify:e2e -- --project=mobile-chrome   # 只跑移动端项目
bun run verify:e2e -- --headed                  # 有头模式目视观察
bun run verify:e2e -- -g "星系核心"              # 按用例名过滤
```

## 3. 前置条件

| 条件 | 说明 | 不满足时 |
| --- | --- | --- |
| 依赖完整 | `node_modules` 已安装（`bun install`） | 脚本预检终止并提示 |
| 数据底座就绪 | `data/wenqi.db` 存在且 > 1MB（14,181 位诗人、192,385 条关系） | 脚本预检终止并提示 |
| 系统 Chrome | Playwright 以 `channel: 'chrome'` 复用本机 Chrome，不下载浏览器 | 脚本预检终止并提示 |
| 3000 端口 | 脚本自动清理残留进程，无需手工处理 | — |

## 4. 幂等性设计

「幂等」指：**无论此前发生过什么（上次运行失败、dev server 残留、旧报告堆积），每次运行都从确定性的干净状态出发，结果只取决于当前代码与数据**。为此脚本在每轮运行前执行：

| 幂等问题 | 对策 |
| --- | --- |
| `playwright.config.ts` 的 `reuseExistingServer: true` 会复用 3000 端口上残留的**旧代码** dev server，导致验证失真 | 运行前用 `netstat` + `taskkill` 终止 3000 端口监听进程，强制 Playwright 以当前代码自启 dev server |
| `e2e-report/`（HTML 报告）与 `test-results/`（失败截图/trace）随轮次累积 | 运行前整目录清空重建 |
| 用例间状态泄漏（localStorage、收藏、聚焦态） | 每条用例使用独立浏览器上下文；`helpers.ts` 的 `gotoGalaxy` 预置欢迎标记，不依赖真实首访顺序 |
| 数据资产被写入 | 数据库与分片数据全程只读 |

## 5. 执行流程

脚本 `scripts/verify-e2e.ts` 按四个阶段顺序执行：

1. **环境预检**：依赖、数据底座、系统 Chrome、用例目录四项检查，任一失败即终止（fail-fast），提示处理方式。
2. **幂等清理**：终止 3000 端口残留进程；清空 `e2e-report/`、`test-results/`。
3. **执行 Playwright E2E**：启动 `bunx playwright test`（实时回显输出并捕获），dev server 由 Playwright 自行拉起与关闭。
4. **汇总报告**：解析用例行与汇总行，生成 Markdown 验证报告并写入 `e2e-report/`。

## 6. 覆盖范围

| 执行项目 | 设备/环境 | 用例 | 覆盖业务 |
| --- | --- | --- | --- |
| `desktop-chrome` | 1440×900 桌面 Chrome | `galaxy.spec.ts` | 星系核心闭环：初始化 14,181 节点 → 搜索「李白」→ 三气评分与评分构成 → 关系图谱（hover 证据、点击跳转聚焦）→ 行迹地图（轨迹折线、停靠点）→ 收藏星单 → ESC 关闭 |
| `desktop-chrome` | 同上 | `interactions.spec.ts` | 每日一诗、双诗人对比（切换对比对象）、语义检索（意境词「孤寂」命中「意境」徽标）、分享链接与诗词卡片导出、分享还原、时间轴回放（播放/暂停/速度循环 1×→2×→4×/区间拖拽统计随动/复位恢复全量）、维度预设、地理模式、无障碍设置 |
| `desktop-chrome` | 同上 | `tour.spec.ts` | 主题漫游：选剧本 → 播放 → 翻步 → 暂停 → 退出 |
| `mobile-chrome` | Pixel 5 移动模拟 | `mobile.spec.ts` | 底部导航四项、维度/分享/设置面板、搜索与详情抽屉 |
| `no-webgl` | 禁用 WebGL/Canvas | `fallback.spec.ts` | 渲染降级：文字模式兜底页完整可用 |

全部用例单 worker 串行执行（`fullyParallel: false`），全量耗时约 1.5 分钟，满足 08 文档「E2E < 3 分钟」要求。

## 7. 结果与报告解读

### 7.1 终端输出

- 预检、清理动作逐行打印（`✓ / ✗ / ·` 标记）；
- Playwright 输出实时回显；
- 结束打印每条用例状态表与汇总（通过/失败/跳过、总耗时、报告路径）。

### 7.2 报告文件

每次运行生成 `e2e-report/verify-<YYYYMMDDHHMMSS>.md`，结构：

1. **结论行**：通过/未通过、通过数、耗时、Playwright 退出码；
2. **环境预检表**：四项检查结果；
3. **幂等清理动作**：本轮实际执行的清理记录；
4. **用例结果表**：状态、执行项目、用例名、耗时；
5. **附录**：Playwright 完整 stdout/stderr（失败时可直接定位断言与错误栈）。

HTML 交互报告仍由 Playwright 生成于 `e2e-report/index.html`，可用 `bunx playwright show-report` 打开；失败 trace 位于 `test-results/`，用 `bunx playwright show-trace <zip>` 回放。

### 7.3 退出码

| 退出码 | 含义 |
| --- | --- |
| `0` | 全部通过 |
| `1` | 预检未通过，或存在失败用例 |

## 8. 常见问题排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 预检报「数据底座缺失」 | 未执行数据入库管道 | 按 09-部署运行服务文档执行 `bun run data:all` / `bun run db:import` |
| 预检报「未找到 Chrome」 | 本机未安装 Chrome | 安装 Chrome，或将 `playwright.config.ts` 的 `channel: 'chrome'` 改为默认 Chromium |
| 大量用例同报资源 404 / 超时 | dev server 启动失败或数据分片缺失 | 查看 `e2e-report/verify-*.md` 附录 stderr；确认 `public/data/` 产物存在 |
| 单条用例失败且错误含「拦截 pointer events / element is not stable」 | UI 元素互相遮挡或动画未收敛，通常是真实缺陷 | 以失败截图（`test-results/`）与 trace 回放定位；参考 0.5.7 移动端面板叠加缺陷的先例 |
| 用例偶发超时（`gotoGalaxy` 150s） | 首次冷启动编译慢 | 预热一次 `bun run dev` 后重跑 |

## 9. 新增用例的幂等约定

向 `e2e/` 添加用例时，须遵守：

1. **不依赖运行顺序**：每条用例自带完整前置（`gotoGalaxy`），不假设其他用例留下的收藏、聚焦或面板状态；
2. **预置存储标记**：进入页面操作前用 `addInitScript` 预置 `wenqi_welcome_shown`，跳过首访引导遮挡；
3. **不写共享数据**：用例不得写入数据库、`public/data/` 分片等文件资产；收藏等交互仅落在浏览器独立上下文内；
4. **结束态清理**：用例内打开的面板/聚焦态按业务路径关闭（点击或 ESC），断言面板隐藏后再结束；
5. **测试数据自描述**：断言使用确定性数据（如「李白」、节点总数 14,181），不依赖「每日一诗」等随机内容的具值。
