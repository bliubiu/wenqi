## 1. 项目背景与愿景

### 1.1 项目缘起

「文气」一词源自曹丕《典论·论文》：「文以气为主，气之清浊有体，不可力强而致。」古典文学批评自古即以「气」论文章高下、品性风骨。本项目将这一传统美学概念数字化、空间化，构建一座可漫游、可凝视、可呼吸的「古典文学星系」。

### 1.2 项目愿景

构建一个以**三维星系可视化**为载体、以**古典文学经典**（诗、词、曲、文）为内容、以**「文气」流动**为美学语言的沉浸式知识探索产品。让用户在「观气—聚气—散气」的交互中，感受千年文脉的聚散流转。

### 1.3 核心隐喻

**文脉如气，流动不居。**

- **知识本体即「气」**：每颗星（知识节点）并非静止数据点，而是带有「呼吸」动画的「气点」——脉动、闪烁，如活体宇宙。
- **知识关联即「气流」**：节点之间的边不再是僵硬线条，而是流动光粒或氤氲雾带，模拟「气」在文脉中的流转。
- **知识星云即「气团」**：缩放视角后，整片「文气」弥漫成星云，不同朝代、体裁的气团呈现不同色彩与密度。

### 1.4 价值主张

| 维度 | 传统文学数据库 | 文气（WenQi） |
| --- | --- | --- |
| 知识形态 | 静态表格、列表 | 流动星系、活体宇宙 |
| 探索方式 | 检索—阅读 | 凝视—扰动—汇聚 |
| 美学表达 | 文字为主 | 三维空间 + 韵律 + 节奏 |
| 关系呈现 | 显式链接 | 气流光粒、雾带 |
| 用户感受 | 信息获取 | 沉浸观气 |

## 2. 用户画像

### 2.1 主要用户

#### 画像 A：古典文学爱好者「云观」

- **特征**：对中国古典诗词有浓厚兴趣，但缺乏系统性认知。
- **诉求**：以直观、美学化方式浏览古典文学，发现诗人与作品之间的关联。
- **场景**：闲暇时打开网页，漫游星系，点击感兴趣的诗人，查看其「文气」汇聚的相关作品。
- **关键体验**：视觉震撼 + 低门槛 + 即开即用。

#### 画像 B：文学/历史研究者「砚秋」

- **特征**：具备专业背景，关注影响力、引用关系、时代脉络。
- **诉求**：通过三气维度（才气、人气、运气）进行多维分析，对比不同朝代、流派。
- **场景**：拉远视角观察朝代气团密度，缩放进入特定诗人节点，查看其影响力分布。
- **关键体验**：数据可信 + 维度可调 + 关系可溯。

#### 画像 C：教育工作者「师竹」

- **特征**：中学/高校语文教师，需在课堂展示文学脉络。
- **诉求**：以可视化方式向学生讲解诗人关系、时代特征、体裁演变。
- **场景**：投屏展示星系，按朝代/体裁筛选，聚焦特定诗人讲解。
- **关键体验**：演示流畅 + 筛选灵活 + 中文友好。

#### 画像 D：美学/设计探索者「青衫」

- **特征**：对数据可视化、东方美学、交互艺术感兴趣。
- **诉求**：体验「文气」的视觉与交互美学，寻找灵感。
- **场景**：随意漫游，截图分享，观察粒子流动与气团色彩。
- **关键体验**：画面精致 + 动效流畅 + 可分享。

### 2.2 次要用户

- **数据贡献者**：通过开源数据集贡献诗词元数据（远期）。
- **二次开发者**：基于开放 API 构建衍生应用（远期）。

## 3. 功能需求

### 3.1 功能模块总览

| 模块编号 | 模块名称 | 优先级 | 模块编号 | 模块名称 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| F01 | 星系可视化引擎 | P0 | F06 | 朝代/体裁气团 | P1 |
| F02 | 节点呼吸与气流 | P0 | F07 | 搜索与定位 | P1 |
| F03 | 聚气交互 | P0 | F08 | 诗人/作品详情 | P1 |
| F04 | 散气交互 | P0 | F09 | 三气维度调节 | P2 |
| F05 | 三气坐标轴 | P1 | F10 | 分享与截图 | P2 |

### 3.2 F01 星系可视化引擎（P0）

**目标**：以 Three.js 构建可漫游的三维星系，承载全部知识节点。

**功能要求**：

- F01-1 三维场景初始化，包含相机、光源、星空背景。
- F01-2 支持鼠标/触控的旋转、平移、缩放（OrbitControls）。
- F01-3 节点按三气坐标（X 运气、Y 才气、Z 人气）分布于三维空间。
- F01-4 视角拉远时，节点聚合为气团（LOD 层级细节）。
- F01-5 视角拉近时，节点展开为可点击的星点。
- F01-6 帧率目标：桌面端 60fps，移动端 30fps。

**验收标准**：

- 加载 5000 节点时桌面端可稳定 60fps。
- 缩放过渡平滑无跳跃。
- 节点点击命中区域不小于 12px。

### 3.3 F02 节点呼吸与气流（P0）

**目标**：让节点与边呈现「气」的生命感。

**功能要求**：

- F02-1 节点呼吸动画：基于 sin 波的脉动缩放与亮度变化。
- F02-2 节点闪烁：随机相位偏移，避免整齐划一。
- F02-3 边的气流：沿边路径流动的光粒（Shader 粒子）。
- F02-4 气流速度与节点关联强度正相关。
- F02-5 气流颜色继承起点节点的「气色」。

**验收标准**：

- 呼吸频率 0.5–1.5Hz，肉眼可感知但不眩晕。
- 光粒流动方向明确，不出现方向错乱。
- 性能：10000 条边时帧率不低于 30fps。

### 3.4 F03 聚气交互（P0）

**目标**：点击诗人节点，其「文气」向其汇聚。

**功能要求**：

- F03-1 点击节点触发「聚气」状态。
- F03-2 相关节点（同朝代、同流派、有引用关系）沿曲线向焦点节点汇聚。
- F03-3 汇聚过程伴随光粒加速、雾带收束。
- F03-4 焦点节点放大并高亮，展示诗人名称浮标。
- F03-5 再次点击或点击空白处恢复原状（散气）。
- F03-6 聚气过程可被中断（点击其他节点切换焦点）。

**验收标准**：

- 聚气动画时长 800–1200ms，缓动函数为 ease-out。
- 汇聚节点数量上限 50，避免视觉过载。
- 中断切换无残影、无卡顿。

### 3.5 F04 散气交互（P0）

**目标**：缩放拉远，观察整片「文气」弥漫的星云。

**功能要求**：

- F04-1 视角距离超过阈值时进入「散气」模式。
- F04-2 节点聚合为朝代/体裁气团（F06）。
- F04-3 气团呈现色彩与密度差异。
- F04-4 散气状态下可点击气团聚焦进入该气团。
- F04-5 散气→聚气过渡平滑，无突变。

**验收标准**：

- 阈值切换有 300ms 过渡。
- 气团边界柔和（高斯模糊或体积雾）。
- 散气模式下帧率不低于 45fps。

### 3.6 F05 三气坐标轴（P1）

**目标**：以 XYZ 轴承载三气维度，构建「观气」坐标系。

**功能要求**：

- F05-1 X 轴 = 运气（时间轴上的偶然性与历史机遇）。
- F05-2 Y 轴 = 才气（作品创造力、独特性评分）。
- F05-3 Z 轴 = 人气（影响力、被引用次数、知名度）。
- F05-4 坐标轴可选显隐，避免遮挡节点。
- F05-5 坐标轴标注中文标签与刻度。
- F05-6 节点坐标由数据驱动，可动态更新。

**评分规则（领域规则，详见领域模型文档）**：

- 才气（0–100）：基于用词独特性、意象新颖度、体裁创新。
- 人气（0–100）：基于后世引用次数、入选教材次数、搜索热度。
- 运气（−50 ~ +50）：基于生卒年间的政治环境、被发现/重评的时机。

### 3.7 F06 朝代/体裁气团（P1）

**目标**：散气模式下以气团呈现朝代与体裁分布。

**功能要求**：

- F06-1 朝代气团：先秦、汉、魏晋南北朝、唐、宋、元、明、清、近现代。
- F06-2 体裁气团：诗、词、曲、赋、文、小说。
- F06-3 气团色彩规范：
  - 唐诗：黄金气团 `#D4A24C`
  - 宋词：银蓝气团 `#7BA7D9`
  - 元曲：赭红气团 `#B5523E`
  - 魏晋：青绿气团 `#6FAE8E`
  - 先秦：玄青气团 `#3A4A5C`
  - 明清：紫灰气团 `#8C6FAE`
- F06-4 气团密度由节点数量与平均人气决定。
- F06-5 气团可切换朝代/体裁两种聚类维度。

### 3.8 F07 搜索与定位（P1）

**功能要求**：

- F07-1 全局搜索框，支持诗人名、作品名、诗句全文检索。
- F07-2 搜索结果列表带朝代/体裁标签。
- F07-3 点击结果自动飞行至对应节点并触发聚气。
- F07-4 支持拼音、简繁体模糊匹配。
- F07-5 搜索响应时间 < 200ms（本地索引）。

### 3.9 F08 诗人/作品详情（P1）

**功能要求**：

- F08-1 诗人详情面板：姓名、字号、生卒年、朝代、流派、简介、代表作列表、三气评分雷达图。
- F08-2 作品详情面板：标题、体裁、创作时间、原文（竖排或横排可选）、注释、译文、相关诗人。
- F08-3 面板可拖动、可关闭、可固定。
- F08-4 原文支持朗读（Web Speech API，远期）。

### 3.10 F09 三气维度调节（P2）

**功能要求**：

- F09-1 侧边栏滑块调节三气权重，实时影响节点位置。
- F09-2 可保存自定义视图配置（localStorage）。
- F09-3 预设视图：经典视图、才气优先、人气优先、运气优先。

### 3.11 F10 分享与截图（P2）

**功能要求**：

- F10-1 一键截图当前视角（html2canvas 或 Three.js 渲染输出）。
- F10-2 生成带项目水印的分享图。
- F10-3 分享链接携带视角参数（相机位置、焦点节点）。

## 4. 三气维度模型

### 4.1 维度定义

| 维度 | 轴 | 取值范围 | 含义 | 数据来源 |
| --- | --- | --- | --- | --- |
| 才气 | Y | 0–100 | 作品创造力、独特性 | 文本分析算法 + 人工标注 |
| 人气 | Z | 0–100 | 影响力、被引用次数 | 后世引用、教材入选、搜索热度 |
| 运气 | X | −50 ~ +50 | 时间轴上的偶然性与历史机遇 | 生卒年政治环境、重评事件 |

### 4.2 评分原则

- **可解释**：每项评分须可追溯至原始数据与算法。
- **可争议**：评分仅作可视化参考，不作为权威定论，UI 须明示「仅供参考」。
- **可演进**：评分算法版本化，历史版本可回溯。

### 4.3 视觉编码

- 节点大小：人气（Z）归一化映射至半径 2–8px。
- 节点亮度：才气（Y）归一化映射至 0.4–1.0。
- 节点色相：朝代主色 + 才气微调（才气越高色相越纯）。
- 节点位置：X 运气、Y 才气、Z 人气。

## 5. 非功能需求

### 5.1 性能

| 指标 | 桌面端 | 移动端 |
| --- | --- | --- |
| 首屏加载（含字体） | ≤ 3s | ≤ 5s |
| 节点渲染帧率 | 60fps | 30fps |
| 散气模式帧率 | 45fps | 30fps |
| 搜索响应 | < 200ms | < 300ms |
| 聚气动画 | 800–1200ms | 800–1200ms |
| WASM 初始化 | < 500ms | < 800ms |

### 5.2 兼容性

- 桌面浏览器：Chrome ≥ 90、Edge ≥ 90、Firefox ≥ 88、Safari ≥ 14。
- 移动浏览器：iOS Safari ≥ 14、Android Chrome ≥ 90。
- 需支持 WebGL 2.0，降级 WebGL 1.0。
- 不支持 WebGL 时显示文字版兜底页面。

### 5.3 可访问性

- 提供键盘导航：方向键旋转、+/- 缩放、Enter 聚气、Esc 散气。
- 提供高对比度模式。
- 文字内容支持屏幕阅读器（ARIA 标签）。
- 尊重 `prefers-reduced-motion`，关闭呼吸与气流动画。

### 5.4 国际化与本地化

- 首版仅支持简体中文。
- 文案与数据分离，预留 i18n 接口。
- 中文字体内嵌：Noto Sans SC（SIL 协议）+ 系统默认字体保底。

### 5.5 安全与隐私

- 不收集用户个人信息，无账号体系（首版）。
- 视图配置仅存于 localStorage。
- 分享链接不含用户身份数据。
- 日志严格脱敏，禁止记录敏感信息（详见架构文档日志系统章节）。

### 5.6 可维护性

- 前后端分离，Rust WASM 与 TypeScript 通过明确接口通信。
- DDD 四层架构，领域逻辑独立于框架。
- TDD：核心领域逻辑测试覆盖率 ≥ 80%。
- 文档与代码同仓库，随版本演进。

### 6.1 开源数据集

| 数据集 | 内容 | 协议 | 用途 |
| --- | --- | --- | --- |
| 中华古诗词数据集（chinese-poetry） | 诗、词、曲、文言文 | MIT | 作品原文、作者、朝代 |

| 全唐诗/全宋词开源整理 | 作者元数据 | 公共领域 | 生卒年、字号 |

### 6.2 数据加工

- 原始数据 → 清洗（去重、纠错）→ 富化（补充三气评分）→ 索引（全文检索）。
- 加工后的数据以 JSON / SQLite 形式随应用分发，支持离线运行。
- 数据版本化，每次更新记录变更日志。

### 6.3 数据范围（完整版目标）

- 诗人：≥ 2000 位
- 作品：≥ 50000 首
- 朝代覆盖：先秦至近现代
- 体裁覆盖：诗、词、曲、赋、文、小说
