## 1. 设计目标

### 1.1 核心原则

**纯客户端离线可用。** 持久化是文气项目的横切关注点，通过浏览器原生存储 API 实现数据持久化，确保应用离线可用。

1. **纯客户端**：所有持久化均在浏览器内完成，无后端服务依赖。
2. **端口抽象**：领域层定义持久化端口，基础设施层提供浏览器实现。
3. **版本契约**：数据集版本与评分算法版本共同构成缓存键，任一升级即失效重建。
4. **离线优先**：首屏后所有交互不依赖网络，二次访问零网络依赖。
5. **日志合规**：严格遵循 AGENTS.md 日志规范（IndexedDB 存储 + 按日轮转 + 32 天保留 + 脱敏 + 导出下载）。

### 1.2 设计约束

- 纯客户端应用，无后端服务（数据随应用分发）。
- 持久化实现基于浏览器原生 API（IndexedDB、localStorage、Cache API）。
- 持久化实现不得泄露敏感信息，遵循脱敏策略。

## 2. 存储选型

文气项目在浏览器环境中使用三种存储机制，各司其职。

### 2.1 存储机制总览

| 存储机制 | 用途 | 容量 | 访问方式 | 持久性 |
|---------|------|------|---------|--------|
| localStorage | 视图配置 | 5–10MB | 同步 | 永久 |
| IndexedDB | 数据集、索引、评分、日志 | 数百 MB | 异步 | 永久 |
| Cache API | 静态资源（WASM、字体、分片） | 数百 MB | 异步 | 永久 |

### 2.2 数据分类与存储映射

| 数据类型 | 数据规模 | 访问频率 | 变更频率 | 存储机制 |
|---------|---------|---------|---------|---------|
| 用户视图配置 | < 5KB | 每次访问 | 用户操作时 | localStorage |
| 数据集（诗人/作品/关联） | 10–50MB | 启动加载 | 版本升级时 | IndexedDB |
| WASM 空间索引二进制 | 5–20MB | 启动加载 | 算法升级时 | IndexedDB（Blob） |
| WASM 倒排索引二进制 | 5–15MB | 启动加载 | 算法升级时 | IndexedDB（Blob） |
| 三气评分结果 | 1–5MB | 偶尔查询 | 算法升级时 | IndexedDB |
| 静态资源（WASM/字体/分片） | 5–10MB | 首次加载 | 版本升级时 | Cache API |
| 日志 | 增长型 | 持续写入 | 持续 | IndexedDB |

### 2.3 localStorage（视图配置）

- **用途**：相机位置、焦点节点、维度权重、主题偏好。
- **理由**：同步访问、容量充足（5–10MB）、API 简单。
- **限制**：仅存可序列化的小数据，不存对象引用。

### 2.4 IndexedDB（数据集与索引缓存）

- **用途**：数据集 JSON、WASM 索引二进制、评分结果、日志。
- **理由**：大容量（数百 MB）、支持 Blob、事务性、异步非阻塞。
- **数据库结构**：

| 对象存储 | 键 | 值 | 索引 |
| --- | --- | --- | --- |
| `data_cache` | 文件名（如 `nodes.json`） | 数据集 JSON | — |
| `logs` | 自增主键 | 日志条目 | `timestamp`, `level` |

> **说明**：`DataLoader` 使用统一 `data_cache` 对象存储，以文件名为键缓存 JSON 数据。  
> 空间索引数据（`spatial-index.json`）同样缓存于 `data_cache`，读取后由 JS 端 `WasmBridge` 惰性构建 KD-Tree。  
> bincode 序列化标记（`SerializationFormat`）已定义在 `DataLoader.ts` 中，当前实现使用 JSON + IndexedDB 结构化克隆，未来如引入文件存储场景可启用 bincode。

### 2.5 Cache API（静态资源）

- **用途**：WASM 模块、字体子集、数据分片。
- **理由**：与 Service Worker 协同、支持 Request/Response 模型、浏览器原生管理。
- **策略**：hash 命名 + `immutable` 缓存，版本升级自动失效。

## 3. 版本契约

### 3.1 借鉴诗云字库冻结契约

诗云字库一旦冻结不可变，否则所有编号失效、分享链接断裂。文气建立类似的双版本契约：

- **数据集版本**（`data.version`）：数据集内容变更标识。
- **评分算法版本**（`scoring.algorithmVersion`）：三气评分算法变更标识。

二者共同构成缓存键。任一升级 → 对应缓存失效，自动清理重建。

### 3.2 版本校验流程

```text
启动 → 读取 application.yml 中的期望版本
  → 查询本地缓存的实际版本
  → 比对
    ├─ 一致 → 直接加载缓存（快速启动）
    ├─ 数据集版本不一致 → 清理 dataset + indexCache + scores，重新加载
    └─ 算法版本不一致 → 清理 indexCache + scores，重建索引与评分
```

### 3.3 版本升级策略

| 升级类型 | 影响范围 | 处理策略 |
| --- | --- | --- |
| 数据集小版本（增补数据） | 仅 dataset | 增量更新，保留旧评分 |
| 数据集大版本（结构调整） | dataset + indexCache | 全量重建 |
| 评分算法小版本（参数调整） | scores | 重算评分，保留索引 |
| 评分算法大版本（模型重构） | scores + indexCache | 全量重建 |

### 3.4 永久链接兼容性

借鉴诗云永久链接契约，文气分享链接须包含版本信息：

```text
#a=<诗人Id>&v=<数据集版本>&s=<算法版本>
```

- 版本一致：直接还原视图。
- 版本不一致：提示用户"数据已更新，正在重新定位"，后台重新计算节点位置后还原。

### 3.5 数据分片策略

为优化首屏加载性能，大规模数据集按朝代或体裁分片存储，支持按需加载。

#### 3.5.1 分片规则

| 分片维度 | 分片方式 | 分片数量 | 单片规模 |
| --- | --- | --- | --- |
| 按朝代（默认） | 每个朝代一个分片 | 9 片 | 500–2000 诗人 |
| 按体裁 | 每个体裁一个分片 | 6 片 | 1000–3000 作品 |

#### 3.5.2 分片文件命名

```text
data/processed/
├── poets-001-pre_qin.json      # 先秦诗人
├── poets-002-han.json          # 汉代诗人
├── poets-003-wei_jin.json      # 魏晋南北朝诗人
├── poets-004-tang.json         # 唐代诗人
├── poets-005-song.json         # 宋代诗人
├── poets-006-yuan.json         # 元代诗人
├── poets-007-ming.json         # 明代诗人
├── poets-008-qing.json         # 清代诗人
├── poets-009-modern.json       # 近现代诗人
├── works-001-shi.json          # 诗
├── works-002-ci.json           # 词
├── works-003-qu.json           # 曲
├── works-004-fu.json           # 赋
├── works-005-wen.json          # 文
└── works-006-xiaoshuo.json     # 小说
```

#### 3.5.3 加载策略

| 场景 | 加载范围 | 说明 |
| --- | --- | --- |
| 首屏初始化 | 当前视角朝代分片 + 索引元数据 | 快速呈现部分星系 |
| 完整加载 | 全部分片（后台异步） | 用户漫游时逐步加载 |
| 搜索触发 | 按需加载目标朝代/体裁分片 | 搜索结果跨分片时动态加载 |
| 散气模式 | 全部朝代分片 | 气团计算需要全量数据 |

#### 3.5.4 分片配置

在 `application.yml` 中配置：

```yaml
data:
  source: data/processed/dataset.json
  version: 2026.06.01
  shards:
    enabled: true
    by: dynasty                # dynasty 或 genre
    preloadAll: false          # 是否启动时加载全部分片
    lazyLoadOnSearch: true     # 搜索时按需加载
```

#### 3.5.5 分片与缓存协同

- 每个分片独立缓存于 IndexedDB，键为 `shard-<维度>-<标识>`。
- 分片版本跟随数据集版本（`data.version`），版本升级时全部分片失效。
- 分片支持增量更新：仅下载变更的分片文件（通过 manifest 比对 hash）。

## 4. DDD 端口抽象

### 4.1 端口定义

领域层定义端口接口，基础设施层提供浏览器 IndexedDB 实现。

```text
┌─────────────────────────────────────────────────┐
│  领域层（定义端口）                              │
│  ├─ DatasetRepository       数据集仓储           │
│  ├─ IndexCacheRepository    索引缓存仓储         │
│  ├─ ScoreCacheRepository    评分缓存仓储         │
│  ├─ ViewConfigRepository    视图配置仓储         │
│  └─ LoggerPort              日志端口             │
└────────────────────┬────────────────────────────┘
                     │ 实现
┌────────────────────▼────────────────────────────┐
│  基础设施层（浏览器 IndexedDB 实现）             │
│  └─ IndexedDBRepository                         │
└─────────────────────────────────────────────────┘
```

### 4.2 端口接口定义

#### 4.2.1 `DatasetRepository`（数据集仓储）

```typescript
interface DatasetRepository {
  // 加载数据集（优先缓存，其次网络）
  load(version: string): Promise<Dataset>;

  // 校验缓存版本
  getCachedVersion(): Promise<string | null>;

  // 写入缓存
  saveCache(dataset: Dataset, version: string): Promise<void>;

  // 清理过期缓存
  clearCache(): Promise<void>;

  // 获取数据集清单
  getManifest(): Promise<DatasetManifest>;
}
```

#### 4.2.2 `IndexCacheRepository`（索引缓存仓储）

```typescript
interface IndexCacheRepository {
  // 读取缓存的索引二进制
  read(algorithmVersion: string, indexType: IndexType): Promise<Blob | null>;

  // 写入索引二进制
  write(algorithmVersion: string, indexType: IndexType, data: Blob): Promise<void>;

  // 校验缓存有效性
  isValid(algorithmVersion: string): Promise<boolean>;

  // 清理缓存
  clear(): Promise<void>;
}

type IndexType = 'SPATIAL_KDTREE' | 'INVERTED_INDEX' | 'CLUSTER_INDEX';
```

#### 4.2.3 `ScoreCacheRepository`（评分缓存仓储）

```typescript
interface ScoreCacheRepository {
  // 批量读取评分
  readBatch(refIds: string[]): Promise<Map<string, ThreeQi>>;

  // 批量写入评分
  writeBatch(scores: Map<string, ThreeQi>, algorithmVersion: string): Promise<void>;

  // 按算法版本清理
  clearByAlgorithm(version: string): Promise<void>;
}
```

#### 4.2.4 `ViewConfigRepository`（视图配置仓储）

```typescript
interface ViewConfigRepository {
  load(): Promise<ViewConfig | null>;
  save(config: ViewConfig): Promise<void>;
  clear(): Promise<void>;
}

interface ViewConfig {
  cameraPosition: [number, number, number];
  cameraTarget: [number, number, number];
  focusedNodeId: string | null;
  dimensionWeights: DimensionWeights;
  clusterDimension: 'DYNASTY' | 'GENRE';
  theme: 'default' | 'high-contrast';
  reducedMotion: boolean;
}
```

#### 4.2.5 `LoggerPort`（日志端口）

```typescript
interface LoggerPort {
  debug(module: string, message: string, context?: object): void;
  info(module: string, message: string, context?: object): void;
  error(module: string, message: string, error?: Error): void;
  setLevel(level: 'DEBUG' | 'INFO' | 'ERROR'): void;
  flush(): Promise<void>;

  // 日志轮转（按日清理超过 retentionDays 的记录）
  rotate(retentionDays: number): Promise<void>;

  // 导出日志（生成 wenqi-YYYYMMDD.log 文件下载）
  export(startDate: Date, endDate: Date): Promise<Blob>;
}
```

### 4.3 实现约束

- 仓储返回领域对象，非 DTO。
- 仓储不参与业务逻辑，仅负责持久化与重建。
- 所有实现须处理序列化/反序列化异常，转换为领域异常。
- 写入操作须幂等，重复写入不报错。

## 5. IndexedDB 实现架构

### 5.1 整体架构

```text
IndexedDbRepository（基础设施层）
  ├─ Database 初始化（版本迁移）
  ├─ ObjectStore 定义
  │   ├─ dataset
  │   ├─ indexCache
  │   ├─ scores
  │   └─ logs
  ├─ Transaction 封装（读写分离）
  ├─ Cursor 批量读取（避免全量加载）
  └─ 错误处理（配额超限、连接失败）
```

### 5.2 数据集加载流程

```text
1. CompositionRoot.initialize() → WasmBridge.init()（WASM 搜索模块加载）
2. InitializeUseCase.execute()
3. DataLoader 并行加载数据集
   ├─ 检查内存缓存 Map → 命中直接返回
   ├─ 未命中 → 检查 IndexedDB（data_cache 对象存储）
   │   └─ 命中 → 载入内存缓存，返回（< 100ms 快速路径）
   └─ IndexedDB 未命中 → 网络加载
       ├─ fetch('data/processed/{filename}.json')
       ├─ 写入 IndexedDB 缓存
       ├─ 载入内存缓存
       └─ 返回数据
4. 返回 GalaxyInitData（nodes / poets / scores / poetMap / scoreMap）
5. 表现层渲染星系
6. WasmBridge 惰性加载 spatial-index.json，构建 JS 端 KD-Tree
   （首次 queryNearby 调用时触发，非启动阻塞）
```

### 5.3 空间索引策略

空间索引不经过 WASM 构建，由 JS 端 `WasmBridge` 实现：

```text
首次 queryNearby(x, y, z, radius) 调用
  → ensureSpatialIndex()
    ├─ DataLoader.loadSpatialIndex() 从缓存/网络加载 spatial-index.json
    ├─ 提取节点位置数据 → Map<nodeId, Position>
    └─ 构建 JS KD-Tree（KdTreeNode）→ kdRoot

后续 queryNearby 调用 → kdRangeQuery(kdRoot, ...) O(log n)
```

**特点**：
- 惰性初始化：不阻塞启动流程。
- 纯 JS 实现：不依赖 WASM，无序列化开销。
- 数据源 `spatial-index.json` 缓存于 IndexedDB 的 `data_cache` 对象存储。

### 5.4 配额管理

IndexedDB 配额有限（通常为磁盘可用空间的一定比例），须监控：

- 写入前检查 `navigator.storage.estimate()`。
- 配额不足时按优先级清理：日志 > 旧版本评分 > 旧版本索引 > 数据集缓存。
- 请求持久化存储权限：`navigator.storage.persist()`，避免浏览器自动清理。

## 6. 日志持久化实现

### 6.1 实现方案

AGENTS.md 要求文件输出 + 按日轮转 + 32 天保留，浏览器环境使用 IndexedDB 实现：

```text
LoggerPort 浏览器实现
  ├─ 日志写入 IndexedDB（logs 对象存储）
  │   ├─ 字段：timestamp, level, module, message, context, stack?
  │   └─ 索引：timestamp（按日查询）、level（按级别过滤）
  ├─ 按日轮转
  │   ├─ 启动时调用 rotate(32)
  │   └─ 清理 timestamp < (now - 32天) 的记录
  ├─ 导出功能
  │   ├─ 用户点击"导出日志"
  │   ├─ 按日期范围查询
  │   ├─ 格式化为 [YYYY-MM-DD HH:MM:SS.SSS] [级别] [线程ID|进程ID] [模块:行号] - 日志内容
  │   └─ 生成 wenqi-YYYYMMDD.log 文件下载
  └─ 控制台同步输出（开发环境）
```

### 6.2 日志格式规范

```
[2026-06-23 14:30:15.123] [INFO] [1|1024] [WasmBridge:42] - WASM 模块初始化完成 | {"durationMs":312}
```

- 时间戳：本地时间，不含时区，格式 `YYYY-MM-DD HH:MM:SS.SSS`。
- 级别：`DEBUG` / `INFO` / `ERROR`。
- 线程ID|进程ID：浏览器环境用 `1|<tabId>`。
- 模块:行号：调用方提供。
- 日志内容：统一中文，结构化上下文以 JSON 附录。

### 6.3 脱敏策略（强制）

| 字段类型 | 脱敏方式 | 示例 |
| --- | --- | --- |
| 密码/令牌 | 完全禁止记录 | — |
| 完整身份证号 | 中间打码 | `110101********1234` |
| 手机号 | 中间打码 | `138****5678` |
| 邮箱 | 用户名打码 | `z***@example.com` |
| 用户输入文本 | 仅记录长度与哈希 | `len=12, hash=a1b2c3` |

所有外部输入入库前必须经 `sanitize()` 工具函数处理。

## 7. 数据迁移

### 7.1 迁移场景

| 场景 | 触发条件 | 迁移内容 |
| --- | --- | --- |
| 数据集版本升级 | `data.version` 变更 | 旧数据集 → 新数据集，重建索引 |
| 评分算法升级 | `scoring.algorithmVersion` 变更 | 旧评分 → 新评分，保留节点位置 |

### 7.2 迁移流程

```text
1. 检测版本变更
2. 备份旧数据（临时存储）
3. 执行迁移
   ├─ 数据集迁移：加载新数据集，保留用户配置
   ├─ 索引重建：WASM 重新构建，写入新缓存
   └─ 评分重算：批量调用 ScoringService，写入新缓存
4. 校验迁移结果
   ├─ 成功 → 清理旧数据 + 备份
   └─ 失败 → 回滚至旧数据，记录错误日志
5. 记录迁移日志（中文，脱敏）
```

### 7.3 迁移安全

- 迁移前自动备份，失败可回滚。
- 迁移过程显示进度（避免用户以为卡死）。
- 迁移失败时保留旧数据可用，不中断服务。
- 迁移日志记录起止时间、影响范围、结果。

## 8. 配置集成（application.yml）

持久化相关配置纳入统一入口 `application.yml`：

```yaml
# 文气项目统一配置文件
version: "1.0.0"

persistence:
  # 数据集持久化
  dataset:
    cache: indexedDB
    versionKey: "data.version"
    autoUpdate: true          # 启动时自动检查版本

  # 索引缓存
  index:
    cache: indexedDB
    versionKey: "scoring.algorithmVersion"
    serialization: bincode    # Rust 二进制序列化

  # 评分缓存
  scores:
    cache: indexedDB
    versionKey: "scoring.algorithmVersion"

  # 视图配置
  viewConfig:
    storage: localStorage

  # 日志持久化
  logging:
    level: INFO               # DEBUG / INFO / ERROR
    fileOutput: true
    filePath: "logs/"
    retentionDays: 32
    exportEnabled: true       # 启用日志导出功能

  # 存储配额管理
  quota:
    checkBeforeWrite: true
    cleanupPriority:           # 配额不足时清理优先级（高→低）
      - oldLogs
      - oldScores
      - oldIndexCache
      - datasetCache
    requestPersist: true       # 请求持久化存储权限

# 数据源配置
data:
  source: "data/processed/dataset.json"
  version: "2026.06.01"
  shards:
    enabled: true
    by: "dynasty"             # 按朝代分片加载

# WASM 配置
wasm:
  modulePath: "/wasm/wenqi_core.wasm"
  initTimeoutMs: 5000

# 评分算法
scoring:
  algorithmVersion: "v1.0"
  weights:
    talent: 1.0
    popularity: 1.0
    luck: 1.0
```

## 9. 安全与隐私

### 9.1 数据安全

- IndexedDB 数据不跨域共享，遵循同源策略。
- 用户视图配置仅存本地，不上传。
- 缓存数据完整性校验：数据集带 SHA-256 哈希，加载时校验。

### 9.2 日志安全

- 严格遵循脱敏策略（见 6.3）。
- 生产环境默认 INFO 级别，不输出 DEBUG。
- 日志导出文件不含敏感信息（已脱敏）。
