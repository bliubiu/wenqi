## 1. 设计概述

### 1.1 设计目标

- 以 DDD（领域驱动设计）方法对「文气」业务领域建模。
- 领域层与框架解耦，可独立单元测试。
- 模型语言与业务语言一致（Ubiquitous Language），统一中文术语。

### 1.2 战略设计

#### 限界上下文（Bounded Contexts）

| 上下文 | 职责 | 核心概念 |
| --- | --- | --- |
| 星系上下文（Galaxy） | 节点空间布局与可视化编排 | Galaxy、Node、Layout |
| 诗人上下文（Poet） | 诗人实体与生平信息 | Poet、Dynasty、School |
| 作品上下文（Work） | 作品实体与原文管理 | Work、Genre、Text |
| 评分上下文（Scoring） | 三气评分算法与版本管理 | ThreeQi、TalentScore、PopularityScore、LuckScore |
| 关系上下文（Relation） | 诗人/作品间关联与引用 | Relation、Reference |
| 检索上下文（Search） | 全文检索与定位 | Query、SearchResult |

#### 上下文映射

```
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│  星系上下文   │◄─────│  诗人上下文   │◄─────│  作品上下文   │
│  (核心)       │      │  (核心)       │      │  (支撑)       │
└──────┬───────┘      └──────┬───────┘      └──────────────┘
       │                     │
       │                     ▼
       │              ┌──────────────┐
       │              │  评分上下文   │
       │              │  (核心)       │
       │              └──────────────┘
       │
       ▼
┌──────────────┐      ┌──────────────┐
│  关系上下文   │      │  检索上下文   │
│  (支撑)       │      │  (支撑)       │
└──────────────┘      └──────────────┘
```

**关系类型**：

- 「星系上下文」为核心域，依赖其他上下文提供的数据。
- 「诗人上下文」与「作品上下文」为共享内核（Shared Kernel）的延伸。
- 「评分上下文」为核心域，承载三气算法。
- 「关系上下文」「检索上下文」为支撑域。

### 3.2 评分值对象

#### 3.2.1 `TalentScore`（才气）

```typescript
interface TalentScore {
  readonly value: number;          // 0–100
  readonly algorithmVersion: string; // 评分算法版本
  readonly factors: {
    readonly lexicalUniqueness: number;  // 用词独特性 0–100
    readonly imageryNovelty: number;     // 意象新颖度 0–100
    readonly genreInnovation: number;    // 体裁创新 0–100
  };
}
```

**不变式（Invariants）**：

- `0 ≤ value ≤ 100`
- `value = round(lexicalUniqueness * 0.4 + imageryNovelty * 0.4 + genreInnovation * 0.2)`
- 各因子 `0 ≤ factor ≤ 100`

#### 3.2.2 `PopularityScore`（人气）

```typescript
interface PopularityScore {
  readonly value: number;          // 0–100
  readonly algorithmVersion: string;
  readonly factors: {
    readonly citationCount: number;      // 后世引用次数
    readonly textbookCount: number;      // 入选教材次数
    readonly searchHeat: number;         // 搜索热度（归一化 0–100）
  };
}
```

**不变式**：

- `0 ≤ value ≤ 100`
- `value = normalize(citationCount * 0.5 + textbookCount * 0.3 + searchHeat * 0.2)`
- `citationCount ≥ 0`、`textbookCount ≥ 0`

#### 3.2.3 `LuckScore`（运气）

```typescript
interface LuckScore {
  readonly value: number;          // −50 ~ +50
  readonly algorithmVersion: string;
  readonly factors: {
    readonly politicalEnvironment: number; // 政治环境 −25 ~ +25
    readonly rediscoveryEvents: number;    // 重评事件 −25 ~ +25
  };
}
```

**不变式**：

- `−50 ≤ value ≤ 50`
- `value = politicalEnvironment + rediscoveryEvents`
- 各因子 `−25 ≤ factor ≤ 25`

#### 3.2.4 `ThreeQi`（三气合一）

```typescript
interface ThreeQi {
  readonly talent: TalentScore;
  readonly popularity: PopularityScore;
  readonly luck: LuckScore;
  readonly algorithmVersion: string;
}
```

**工厂方法**：

- `ThreeQi.create(talent, popularity, luck)`：校验算法版本一致后创建。
- 算法版本不一致时抛出 `IncompatibleAlgorithmVersionError`。

**聚合内一致性**：

### 5.3 `Galaxy`（星系聚合）

```typescript
class Galaxy {
  readonly nodes: Map<NodeId, Node>;
  readonly clusters: Map<ClusterId, QiCluster>;
  readonly focusedNodeId: NodeId | null;

  // 工厂
  static create(nodes: Node[]): Galaxy;

  // 节点操作
  addNode(node: Node): void;
  removeNode(nodeId: NodeId): void;
  findNode(id: NodeId): Node | null;

  // 聚气
  focusNode(nodeId: NodeId, relations: Relation[]): ConvergenceResult;
  unfocus(): void;

  // 散气
  buildClusters(dimension: 'DYNASTY' | 'GENRE'): QiCluster[];

  // 维度调节
  applyDimensionWeights(weights: DimensionWeights): void;

  // 查询
  getNodesByDynasty(dynasty: DynastyCode): Node[];
  getNodesByGenre(genre: GenreCode): Node[];
}
```

**聚合内一致性**：

- `Node.refId` 必须指向已存在的 `Poet` 或 `Work`。
- 同一时刻最多一个 `focusedNodeId`。
- 聚气状态下相关节点 `state = 'CONVERGING'`，其余 `state = 'IDLE'`。
- `Relation` 数据量较大（上万条）且使用频率低（仅在聚焦时按需查询），不直接持有于 `Galaxy`，通过 `RelationRepository` 按需加载。

## 6. 领域服务（Domain Service）

### 6.1 领域服务总览

| 服务 | 职责 | 实现位置 |
| --- | --- | --- |
| `ScoringService` | 三气评分计算 | 领域层 + WASM 加速 |
| `RelationService` | 关联发现与权重计算 | 领域层 + WASM 加速 |
| `LayoutService` | 节点空间布局计算 | 领域层 + WASM 加速 |
| `ClusterService` | 气团聚类计算 | 领域层 + WASM 加速 |
| `SearchService` | 全文检索 | WASM（倒排索引） |

### 6.2 `ScoringService`

```typescript
interface ScoringService {
  // 计算诗人三气
  scorePoet(poet: Poet, works: Work[]): ThreeQi;

  // 计算作品三气
  scoreWork(work: Work): ThreeQi;

  // 批量重算（数据更新时）
  rescoreAll(poets: PoetAggregate[]): Map<PoetId, ThreeQi>;

  // 算法版本
  readonly algorithmVersion: string;
}
```

**评分规则**：

评分计算全部在**离线数据加工阶段**完成，使用纯 Rust CLI 工具，不依赖外部 NLP 库。

- **才气**：基于全量语料的统计分析，由三因子加权：
  - `用词独特性`（40%）：对全量作品做字符 bigram/trigram 频率统计，诗人用词分布与语料均值的偏差越大，独特性越高。
  - `意象新颖度`（40%）：统计全量语料中每个词的频率，诗人使用的低频词占比越高，新颖度越高。
  - `体裁创新`（20%）：诗人实际创作体裁分布与同代人主流体裁分布的偏差。
- **人气**：统计后世引用次数、教材入选次数、搜索热度（来自数据集）。
- **运气**：基于生卒年的政治环境标签、重评事件列表计算。数据来源为预定义的 JSON 结构化标签表（如「时代标签表」「重评事件表」），由 Rust CLI 读取后计算。

**版本管理**：

- 算法版本号遵循 `vMAJOR.MINOR`。
- MAJOR 变更表示评分模型重构，历史数据需重算。
- MINOR 变更表示参数调整，可平滑过渡。

### 6.3 `RelationService`

```typescript
interface RelationService {
  // 发现与指定节点相关的所有关联（从仓储按需加载）
  findRelated(nodeId: NodeId, relationRepo: RelationRepository): Relation[];

  // 计算两节点间的关联权重
  computeWeight(source: Node, target: Node, relationType: RelationType): number;

  // 批量构建关联（数据初始化时）
  buildAllRelations(poets: PoetAggregate[]): Relation[];
}
```

**权重规则**：

- 同朝代：基础权重 0.3，若同流派 +0.2。
- 引用关系：权重 = `min(citationCount / 10, 1.0)`。
- 影响关系：权重由数据集显式标注。
- 师生/友人：权重 0.6–0.8（数据集标注）。

### 6.4 `LayoutService`

```typescript
interface LayoutService {
  // 初始布局：按三气坐标分布
  computeInitialLayout(nodes: Node[]): Map<NodeId, NodePosition>;

  // 聚气布局：相关节点向焦点汇聚
  computeConvergence(
    focusNode: Node,
    relatedNodes: Node[],
    relations: Relation[]

  // 散气布局：气团中心计算

  // 维度调节后重算

    nodes: Node[],

```

**ConvergenceResult**：

```typescript
interface ConvergenceResult {
  readonly focusId: NodeId;
  readonly movements: Array<{
    nodeId: NodeId;
    from: NodePosition;
    to: NodePosition;
    durationMs: number;
    easing: 'ease-out' | 'ease-in-out';
  }>;
  readonly relatedCount: number;
}
```

**聚气算法**：

- 焦点节点保持原位（或微调至视野中心）。
- 相关节点沿贝塞尔曲线向焦点汇聚，汇聚半径由关联权重决定（权重越大越近）。
- 汇聚上限 50 个节点（按权重排序取前 50）。
- 无关节点淡出（亮度降至 0.2）。

## 11. 领域规则汇总

### 11.1 评分规则

| 规则编号 | 规则 | 实现 |
| --- | --- | --- |
| R-SCORE-01 | 才气 = 用词独特性×0.4 + 意象新颖度×0.4 + 体裁创新×0.2 | `ScoringService.scorePoet` |
| R-SCORE-02 | 人气 = 归一化(引用×0.5 + 教材×0.3 + 搜索×0.2) | `ScoringService.scorePoet` |
| R-SCORE-03 | 运气 = 政治环境 + 重评事件，范围 [−50, 50] | `ScoringService.scorePoet` |
| R-SCORE-04 | 评分算法版本须一致 | `ThreeQiFactory.create` |

### 11.2 布局规则

| 规则编号 | 规则 | 实现 |
| --- | --- | --- |
| R-LAY-01 | 节点 X 坐标 = 运气值 | `LayoutService.computeInitialLayout` |
| R-LAY-02 | 节点 Y 坐标 = 才气值 | 同上 |
| R-LAY-03 | 节点 Z 坐标 = 人气值 | 同上 |
| R-LAY-04 | 节点大小 = 人气归一化映射至 [2, 8] | `NodeFactory` |
| R-LAY-05 | 节点亮度 = 才气归一化映射至 [0.4, 1.0] | `NodeFactory` |
| R-LAY-06 | 聚气上限 50 节点 | `LayoutService.computeConvergence` |

### 11.3 关联规则

| 规则编号 | 规则 | 实现 |
| --- | --- | --- |
| R-REL-01 | 同朝代基础权重 0.3，同流派 +0.2 | `RelationService.computeWeight` |
| R-REL-02 | 引用权重 = min(引用次数/10, 1.0) | 同上 |
| R-REL-03 | 关联不可自环 | `Relation` 不变式 |

### 11.4 气团规则

| 规则编号 | 规则 | 实现 |
| --- | --- | --- |
| R-CLS-01 | 气团按朝代或体裁聚类 | `ClusterService.clusterBy` |
| R-CLS-02 | 气团密度 = 节点数 × 平均人气 | `ClusterService.computeDensity` |

## 12. 测试策略

### 12.1 单元测试重点

- 值对象不变式（边界值、非法值）。

- 领域事件发布与订阅。

describe('TalentScore', () => {
