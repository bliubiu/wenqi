## 1. 诗云项目概览

### 1.1 项目定位

诗云（Poetry Cloud）是一个把中国全历史诗歌放进三维星系的纯静态站点，灵感来自刘慈欣《诗云》与博尔赫斯《巴别图书馆》：

- **32,657 位诗人、933,857 首诗**，每首诗都有自己的坐标。
- **核心哲学**：诗不被储存——给一个编号就能算出第几首诗，反之亦然。
- **100% 静态构建**，无后端，所有索引计算与渲染均在浏览器端完成。

> 核心数据：收录《诗经》至今32,657位诗人、933,857首诗，含佚名与近现代作者；
>
> 宇宙隐喻：诗人为星（亮度=作品数/影响力，李白/杜甫超亮，佚名微光），诗藏坐标，时空轴标朝代，关系网连流派/师承；
>
> 交互：缩放漫游、点星读诗、查生平/注释，搜关键词定位；
>
> 理念：技术存诗意，冷门诗人不湮灭；
>
> 项目用Three.js/React/自然语言处理，代码成诗性仪式

## 2. 核心算法：编号即诗的双射体系

诗云算法的灵魂是**双射（Bijection）**：诗与编号的可逆映射。这是"诗不被储存"哲学的数学基础。

### 2.1 三层目录架构

诗云在同一字库（大小为 N）之上构建三个相互独立的目录：

| 目录 | 覆盖范围 | 基数 | 编码方式 |
| --- | --- | --- | --- |
| **Babel 目录** | 所有长度为 L 的字符串 | N^L | 纯 base-N |
| **格律目录** | 仅近体诗（律绝）有效子集 | Σ Z^z·P^p·R^r | 混合进制乘积 |
| **自由目录** | 任意长度、任意断句的诗 | 可数无穷 | 双射 base-(N+1) |

三者关系：格律目录**嵌套**于 Babel 目录（通过精确嵌入 e: s → g），自由目录是**独立**的变长目录。

### 2.2 Babel 目录：base-N 编号

最基础的目录，借鉴巴别图书馆。一首诗 = L 个字符的序列，每个字符是字库中的 id（0..N-1）。

**关键约定：首字符为最高位。**

```typescript
// 编号：index = Σ cᵢ·N^(L-1-i)
export function babelRank(N: bigint, chars: number[]): bigint {
  let k = 0n;
  for (let i = 0; i < chars.length; i++) k = k * N + big(chars[i]);
  return k;
}

// 反编号：将编号还原为字符序列
export function babelUnrank(L: number, N: bigint, k: bigint): number[] {
  const out = new Array<number>(L);
  for (let i = L - 1; i >= 0; i--) {
    out[i] = Number(k % N);
    k /= N;
  }
  return out;
}
```

**首字符最高位的设计意图**：使共享同一开头前缀的诗占据**连续的高位地址区间**。这是"半编号"前缀搜索的数学基础——一首诗的开头几个字，固定了其编号的高位，从而锁定一个连续区间。

```typescript
// 半编号：前缀 m 个字固定了高 m 位，剩余 L-m 位自由
export function prefixIndex(L: number, N: bigint, prefix: number[]): bigint {
  const padded = prefix.slice(0, L);
  while (padded.length < L) padded.push(0);
  return babelRank(N, padded);
}
export function prefixRange(L: number, N: bigint, locked: number): bigint {
  return N ** big(Math.max(0, L - locked));
}
```

### 2.3 格律目录：混合进制乘积

格律目录是 Babel 目录的**测度为零子集**——仅包含满足平仄与押韵约束的近体诗。重新编号为混合进制乘积，**无需 DFA**（因为近体诗平仄是位置固定的模板）。

#### 2.3.1 四基本律句 + 对/粘

诗云将五言律句按（起式 head, 收式 tail）分为四种：

| 起式 | 收式 | 平仄模板 |
| --- | --- | --- |
| 仄 | 仄 | 仄仄平平仄 |
| 仄 | 平 | 仄仄仄平平 |
| 平 | 仄 | 平平平仄仄 |
| 平 | 平 | 平平仄仄平 |

七言 = 五言前缀两个与五言起式**相反**平仄的字。通过**对**（对句平仄相反）与**粘**（下一联出句粘上一联对句第二字平仄）规则，构建完整的 L 长度平仄串。

```typescript
export function buildVariant(form: FormDef, qiPing: boolean, rhymeFirst: boolean): Variant {
  const { lines, cpl } = form;
  const head: Tone = qiPing ? 0 : 1;
  const lineArr: Tone[][] = [];
  lineArr.push(makeLine(cpl, head, rhymeFirst ? 0 : 1)); // 首句
  let prev = lineArr[0];
  for (let l = 1; l < lines; l++) {
    let cur: Tone[];
    if (l % 2 === 1) {
      // 对句：oppose 出句，强制平收（押韵）
      cur = oppose(prev);
      cur[cur.length - 1] = 0;
    } else {
      // 新联出句：粘上一联对句第二字平仄，仄收
      const stick = prev[1] as Tone;
      cur = makeLine(cpl, stick, 1);
    }
    lineArr.push(cur);
    prev = cur;
  }
  return { qiPing, rhymeFirst, tones: ([] as Tone[]).concat(...lineArr) };
}
```

每个诗体（五绝/七绝/五律/七律）有 2×2=4 个变体（起式平/仄 × 首句入韵/否）。

#### 2.3.2 位置分类与基数公式

每个位置按平仄模板分为三类：

| 位置类型 | 含义 | 自由度 |
| --- | --- | --- |
| 0（仄） | 仄声位 | Zsz（仄声字数） |
| 1（平非韵） | 平声非韵脚位 | Psz（平声字数） |
| 2（韵脚） | 押韵位 | r_q（第 q 韵部的平声字数） |

**格律目录基数公式**：

```
|G_form| = Σ_variant Σ_韵部 q ( Zsz^z · Psz^pf · r_q^rh )
```

其中 z/pf/rh 分别是该变体下仄位/平非韵位/韵脚位的数量。

#### 2.3.3 混合进制编解码

格律编号 s 的布局（MSB→LSB 剥离）：`[variant] [韵部 q] [逐位置自由数字]`。

```typescript
export function regulatedUnrank(lex: Lexicon, form: FormDef, s: bigint): RegPoem {
  // 1. 剥离 variant：逐变体累减，定位所属变体
  // 2. 剥离 韵部 q：在该变体下逐韵部累减
  // 3. 混合进制解码剩余 rem：每位按位置类型取相应字表
  const radices: bigint[] = [];
  for (let i = 0; i < form.L; i++)
    radices.push(kind[i] === 0 ? Zsz : kind[i] === 1 ? Psz : Rsz);
  const digits = mixedDecode(rem, radices);
  // 4. 将数字映射回具体字 id
  for (let i = 0; i < form.L; i++) {
    const d = Number(digits[i]);
    chars[i] = kind[i] === 0 ? lex.zeList[d]
             : kind[i] === 1 ? lex.pingList[d]
             : lex.rhymeMembers[q][d];
  }
  return { form: form.id, variant: vIdx, rhyme: q, chars };
}
```

`regulatedRank` 是其精确逆运算。二者构成严格双射，44+ 往返测试验证。

#### 2.3.4 嵌入与验证

格律目录通过精确嵌入嵌套于 Babel 目录：

```typescript
// 格律编号 s → Babel 编号 g
export function embedToGlobal(lex: Lexicon, form: FormDef, s: bigint): bigint {
  return babelRank(big(lex.N), regulatedUnrank(lex, form, s).chars);
}
// Babel 编号 g → 格律编号 s（若该诗满足格律）
export function globalToRegulated(lex: Lexicon, form: FormDef, g: bigint): bigint | null {
  const chars = babelUnrank(form.L, big(lex.N), g);
  const poem = matchVariant(lex, form, chars);
  return poem ? regulatedRank(lex, form, poem) : null;
}
```

`matchVariant` 是独立的验证器：遍历 4 变体，检查平仄匹配 + 韵脚同韵部。用于反查与测试。

### 2.4 自由目录：双射 base-(N+1) 编号

自由目录是诗云 Step 5 引入的**任意长度**目录，解决新诗/古体无固定长度的问题。

#### 2.4.1 双射进制（Bijective Numeration）

符号集 = 字库 id 0..N-1 + 断行符号 N，采用**双射 base-(N+1)** 进制：

```typescript
export function anyRank(N: number, syms: number[]): bigint {
  const B = big(N + 1);
  let k = 0n;
  for (const s of syms) k = k * B + big(s + 1); // 数字 1..N+1（双射 ⇒ 无前导零冲突）
  return k;
}
export function anyUnrank(N: number, index: bigint): number[] {
  const B = big(N + 1);
  const out: number[] = [];
  let k = index;
  while (k > 0n) {
    k -= 1n;
    out.unshift(Number(k % B)); // 符号 0..N（N = 断行）
    k /= B;
  }
  return out;
}
```

**双射进制的关键优势**：每个非空符号串 ⇄ 唯一正整数（空串 ⇄ 0），**无损**——编号同时编码了字符与断行位置。这使任意长度、任意断句的诗都有可逆编号。

#### 2.4.2 统一编号（Universal Index）

诗云 Step 6 的关键决策：**显示编号统一采用 anyRank**，而非按诗体分目录。

```typescript
// 显示编号 = anyRank(字符 + 断行符号)
const b = anyRank(lex.N, fixedFormSyms(form, chars));
```

这解决了两个问题：
1. **跨诗体冲突**：旧方案中编号 1 在不同诗体下指代不同诗。
2. **自由复刻去重**：一首七绝以自由格式输入，与以七绝格式输入产生相同符号序列 → 相同编号。

统一编号使"一首诗一个编号"成为构造性保证，而非事后去重。

### 2.5 可逆 Feistel 置乱

为使相邻编号在三维空间中分布较远（避免星系中相邻编号挤在一起），诗云对编号施加**可逆 BigInt Feistel 置乱**。

```typescript
// engineApi.ts 中的 scatter 调用
pointForBabelIndex(formId, b) = indexToPoint(scatter(cardinality, BABEL_KEY, b), R)
```

Feistel 网络的特性：
- **可逆**：反转子密钥顺序即可解密，scatter 的逆运算可还原原编号。
- **雪崩效应**：输入微小变化导致输出显著变化，相邻编号 decorrelate。
- **轮函数无需可逆**：仅靠 XOR 的自逆性保证整体可逆。

诗云用此特性将编号空间"打散"到三维星系中，使点击星系任意点都能映射到一个看似随机但确定可逆的编号。

### 2.6 空间映射：编号 ↔ 三维点

诗云建立编号与三维空间点的双向映射：

```
点击星系点 P → indexFromPoint(P, M) → 编号 b → unrank(b) → 诗
已知编号 b → scatter(b) → indexToPoint(scattered, R) → 规范位置 P
```

`indexFromPoint` 将世界点（1/16 单位格点）哈希为确定的大整数，对目录基数 M 取模：

```typescript
function indexFromPoint(p: [number, number, number], M: bigint): bigint {
  const q = (v: number) => BigInt(Math.round(v * 16));
  const seed = ((q(p[0]) * 73856093n) ^ (q(p[1]) * 19349663n) ^ (q(p[2]) * 83492791n)) & U64;
  let out = 0n;
  let need = bitLen(M) + 16;
  let ctr = 0n;
  while (need > 0) {
    out = (out << 64n) | mix(seed ^ (ctr++ * 0x100000001b3n));
    need -= 64;
  }
  return out % M;
}
```

`mix` 是 SplitMix64 风格的位混合函数，保证哈希均匀。这使得：
- **点击虚空** → 算出该点对应的诗（造诗体验）。
- **搜索已知诗** → 飞到其规范散布位置。

## 3. 性能工程

诗云在纯浏览器环境下处理 93 万首诗、3 万诗人、16.6 万粒子，性能工程极为精炼。

### 3.1 纯 BigInt 零依赖引擎

核心引擎 `engine.ts` 是**纯 TypeScript + 原生 BigInt**，零第三方依赖。

- BigInt 处理 N^L 量级的大数（N=12877, L=56 时编号达数百位十进制）。
- 纯函数设计，无副作用，易于测试与并行。
- 44+ 往返测试覆盖所有 rank/unrank 对。

### 3.2 基数缓存与数据集切换失效

`engineApi.ts` 维护按诗体的基数缓存，数据集切换时统一失效：

```typescript
const _babelSize = new Map<FormId, bigint>();
const _gSize = new Map<FormId, bigint>();
onDatasetChange(() => {
  _babelSize.clear();
  _gSize.clear();
});
```

避免重复计算 N^L 与格律目录基数（后者需遍历所有韵部）。

### 3.3 常用字 Lexicon 复用

"常用字"模式（top-K 高频字）不重建 Lexicon，而是**共享全局平仄/韵部数组，仅缩小 pick-list**：

```typescript
function commonLexicon(K: number): Lexicon {
  const full = getDataset().lexicon;
  const pingList = full.pingList.filter((id) => id < k);  // 字库按频率排序，id<K 即常用字
  // rhymeMembers 同样过滤，但 toneClass/rhymeOf 共享
}
```

缓存按 K，数据集切换时清空。这使"格律 × 常用字"组合无需重算全表。

### 3.4 GPU O(1) 颜色 ID 拾取

Step 7 的关键性能突破：用 GPU 颜色 ID 拾取替代 O(29808)/hover 的 CPU 扫描。

- 每个诗人粒子带 `aPickColor` 属性（编码诗人索引）。
- 鼠标悬停时，在光标位置渲染离屏 n×n 窗口。
- 读取像素 → 解码诗人索引。
- 亮度无关，为真正的视觉融合铺路。

### 3.5 星系粒子分层

`three/Galaxy` 用三组粒子构建星系：
- **DUST**：尘埃背景。
- **arm STARS**：旋臂星。
- **BULGE**：密集粒子核（替代旧的发光精灵，使核心平滑）。

高斯点衰减 `exp(-4.5d²)`、指数盘半径、值噪声团块 + 尘埃间隙、HII 结、暖核→蓝臂色彩梯度。画质切换（high/low）可减半粒子数至约 5.9 万并关闭 Bloom，适配弱 GPU。

### 3.6 诗人织入星系

`three/PoetStars` 将 3 万诗人织入同一星系：
- 高斯径向扩散 + armDev ×0.45，使诗人落在**同一四旋臂**上。
- 沿旋臂的色彩梯度。
- 高斯 Y 厚度。
- 名诗人（`data/famousPoets.ts`）以 2.4× 镀金地标渲染。

### 3.7 赠诗弧线层级边束

`three/GiftLines` 用立方贝塞尔曲线 + `BUNDLE=0.3` 拉向星系中心（穷人版层级边束），着色器脉冲从赠者流向受者，端点淡出。权重≥3 为环境弧，选中诗人时绘制干净的 ego 网络。

## 4. 数据接缝与版本契约

诗云的数据接缝设计是其工程成熟度的标志，对文气项目持久化设计有直接启示。

### 4.1 字库冻结契约（核心）

> ⚠ **字库 FREEZE（生产契约）**：每个共享编号永久链接都在基数 N+1 下编码一首诗，字库的**顺序**定义每个字符的符号 id。改变字库内容或顺序会重映射整个双射，静默破坏所有共享链接。

`build-data.mjs` 因此**字节相同地**重新发出已存在的 `charset.json`，并**跳过**任何包含字库外字符的诗（v2 导入跳过 1597 首 sheepzh 诗）。重新派生需显式 `REFLOW_CHARSET=1`，这是**破坏性的、断链的大版本**。

### 4.2 数据集接缝（Provider Seam）

`engineApi` 通过 `src/data/provider.ts::getDataset()` 读取活动数据集：
- 启动时为**占位符**（`placeholderLexicon.ts`：6000 真实 CJK 字 + 假平仄韵）。
- Step-3 资产加载后，构建真实 `PoetryDataset`（`hydrateLexicon(asset)` + charset），调用 `setDataset(real)`。
- **引擎零代码改动**，`engineApi` 通过 `onDatasetChange` 清空缓存。

这是典型的依赖注入 + 端口抽象，与文气项目的 DDD 端口设计一致。

### 4.3 分层资产加载

首屏预算 ≤ 1.3 MB brotli，重型数据按需加载：

| 资产 | 加载时机 | 大小 | git 跟踪 |
| --- | --- | --- | --- |
| manifest.json | 启动 | 1 KB | 是 |
| charset.json | 启动 | 25 KB | 是 |
| lexicon.json | 启动 | 80–120 KB | 是 |
| poets.index.json | 启动 | 0.9–1.1 MB | 是 |
| gifts.json | 启动 | 126 KB | 是 |
| poems/{shard}.json | 按诗人 | 0.9 MB/分片 | 否（235 MB） |
| poems/{shard}.idx.json | 按诗人 | 2–4 KB/分片 | 否 |
| lines/{shard}.json | 按搜索 | 20–60 KB/分片 | 否（791 MB） |
| stars/{shard}.json | 按区域 | 20–60 KB/分片 | 是 |

### 4.4 按诗人 HTTP Range 取片

点击诗人原本需下载整个 ~0.9 MB 的 `poems/{bucket}.json`。诗云的优化：

- `build-data.mjs` 将每个分片写为**一个合法 JSON 对象** + 字节偏移伴随文件 `poems/{bucket}.idx.json = {id:[off,len]}`。
- `load.ts::loadPoetPoems` 发起 HTTP `Range: bytes=off-(off+len-1)`，`JSON.parse` 切片（状态 **206**）。
- `manifest.poemSidecar` 控制是否尝试；整个文件保持合法 JSON，不支持 Range 的主机（返回 200）或无伴随的旧数据**透明回退**到整桶。

这是"渐进增强"的典范：支持 Range 的主机享受 KB 级加载，不支持的主机自动回退。

### 4.5 全行内容索引

`lines/{shard}.json` 索引**每一行**（非仅首行），256 桶按 `fnv32(line)&0xff`。

- 管线的 `lineBucket(s) = (fnv32(s)&0xff)` 与前端的 `hashStr(s)&0xff` 是**同一个 FNV-1a-32**，保证前端加载到管线写入的桶。
- `LINE_CAP=6`：每相同行最多 6 个引用，封顶超常见行的偏斜。
- 行长 ≥4 字，诗内去重。
- 使"疑是地上霜"（非首行）→ 李白《静夜思》可解析。

### 4.6 赠诗网络的字号解析

`gifts.json` 含 4849 条赠诗边 `[fromId, toId, weight]`：
- **裸名匹配**仅同朝代（精度）。
- **号/字别名表**（~250 条，~120 诗人：少陵→杜甫、子瞻→苏轼、香山→白居易、晦庵→朱熹、遗山→元好问…）可跨朝代解析名人引用。
- `findName` 贪心最长已知名（4→3→2 字），2 字名需后接名尾字/角色/标点/结尾的**完整性守卫**，避免"王介甫↛王介"。

### 4.7 朝代规范化

15 个规范朝代键，管线与前端的精确共享。`*末*初` 过渡桶映射到**较晚**时期（gushiwen 约定）；检查 `南北朝` 子串先于 `宋`（避免南朝宋 ≠ Song）；南唐/李煜 → 五代十国。保留 `dynasty_raw` 以可逆。

### 4.8 简体即规范

字库 = 索引 = 搜索脚本，均为**简体**。理由：
- 语料已是简体，运行时无 OpenCC。
- 用户搜索/输入用简体。
- 繁体覆盖会扰动字库 N=12877 与平水韵→格律映射。

`chinese-poetry` 仓库虽被评估但因繁体 + OpenCC 损耗而**未采用**。

## 6. 诗云的已知局限与文气的改进方向

### 6.1 诗云局限

- **无持久化**：诗云纯静态，无客户端持久化，每次访问重新加载。文气须实现全环境持久化（见 06-持久化设计文档）。
- **无日志系统**：诗云无日志，文气须实现跨环境日志（见 03-架构设计文档第 6 章）。
- **无后端**：诗云无后端，文气远期须支持服务端持久化与数据贡献。
- **无名氏处理**：诗云将无名氏/佚名折叠为巨型诗人，待优化。
- **现代诗人朝代精度**：靠手工民国名表，缺生卒年表。

### 6.2 文气的改进方向

- **全环境持久化**：客户端 IndexedDB + 桌面文件系统 + 服务端数据库，端口统一（06-持久化设计文档）。
- **跨环境日志合规**：浏览器降级 IndexedDB + 导出，桌面/服务端文件系统完全合规（03-架构设计文档第 6.7 节）。
- **三气维度评分**：诗云仅按诗体/朝代/格律分类，文气引入才气/人气/运气三维评分，丰富星系维度。
- **聚气/散气交互**：诗云仅虚空点击造诗，文气增加聚气（点击诗人相关节点汇聚）与散气（缩放拉远节点聚合为气团）交互。
- **WASM 引擎**：诗云纯 TS 引擎，文气采用 Rust WASM 提升性能（03-架构设计文档技术栈）。
