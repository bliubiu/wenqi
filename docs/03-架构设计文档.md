## 1. 架构目标

### 1.1 设计原则

1. **DDD 分层**：严格遵循四层架构，领域层不依赖任何框架与外部设施。
2. **TDD 驱动**：核心领域逻辑以测试先行，核心算法覆盖率 100%，领域层整体 ≥ 80%。
3. **关注点分离**：可视化（Three.js）、计算（Rust WASM）、状态（React）各司其职。
4. **可演进性**：模块化边界清晰，便于替换实现（如更换数据源、渲染引擎）。
5. **性能优先**：大规模节点渲染与计算下沉至 WASM，UI 保持流畅。
6. **中文友好**：日志、错误信息、注释统一中文，遵循脱敏策略。

### 1.2 架构约束

- 客户端为主，首版无后端服务（数据随应用分发）。
- 离线可用：首屏后所有交互不依赖网络。
- 浏览器兼容：WebGL 2.0 优先，WebGL 1.0 降级。
- 包体积：首屏 JS+WASM ≤ 800KB（gzip）。

## 2. 技术选型

### 2.1 技术栈总览

| 层次 | 技术 | 版本目标 | 选型理由 |
| --- | --- | --- | --- |
| 计算层 | Rust → WASM | stable | 高性能计算、三气评分、空间索引 |
| 构建工具 | bun | ≥ 1.0 | 极速构建与依赖管理 |
| 语言 | TypeScript | ≥ 5.0 | 类型安全、IDE 友好 |
| 框架 | Next.js | ≥ 16 | 静态导出、路由、SSG |
| UI 库 | React | ≥ 19.2 | 组件化、生态成熟 |
| 3D 渲染 | Three.js | ≥ 0.170 | WebGL 封装、社区活跃 |
| 样式 | Tailwind CSS | ≥ 3.4 | 原子化 CSS、快速构建 |
| 状态管理 | Zustand | ≥ 4 | 轻量、无样板 |
| 数据查询 | 自建仓储 | — | DDD 仓储模式 |
| 测试 | Vitest + wasm-bindgen-test | — | 前端单测 + Rust 单测 |
| 字体 | Noto Sans SC | SIL | 商用无版权风险 |

### 2.2 Rust + WASM 边界

**Rust 负责（计算密集）**：

- 三气评分算法（才气、人气、运气）——离线数据加工阶段调用。
- 全文检索引擎（倒排索引构建 + 双通道自动降级）。
- 通用 bincode 编解码器（`bincodeEncode` / `bincodeDecode`）。
- 聚类算法（`ClusterService`，JS 端有等价实现）。

**TypeScript 负责（交互与渲染）**：

- Three.js 场景管理与渲染。
- React 组件与 UI 状态。
- 用户交互事件处理。
- 动画时间轴与缓动。
- 空间索引（JS KD-Tree，从 `spatial-index.json` 数据惰性构建）。
- 节点布局计算（`LayoutService` 领域服务）。

**通信契约**：

- 通过 `wasm-bindgen` 生成的绑定接口通信。
- 数据交换使用 `serde` 序列化，**双通道自动降级**：
  - **默认通道**：`SearchEngine.search` —— JSON 字符串，开发友好。
  - **优先通道**：`SearchEngine.searchBinary` —— bincode 二进制 `Uint8Array`，省去 JSON 序列化开销。
  - **通用编解码器**：`bincodeEncode` / `bincodeDecode` —— 将 JSON 字符串视为不透明 String 做 bincode 编解码。
  - **降级策略**：JS 端 `WasmBridge.search` 优先尝试 bincode 通道，失败时静默降级到 JSON 通道。

## 3. DDD 四层架构

### 3.1 分层总览

```
┌─────────────────────────────────────────────────────────┐
│  表现层 Presentation                                     │
│  React Components · Three.js Scene · UI State            │
├─────────────────────────────────────────────────────────┤
│  应用层 Application                                      │
│  Use Cases · DTO · 事务编排 · 任务调度                   │
├─────────────────────────────────────────────────────────┤
│  领域层 Domain                                           │
│  Entities · Value Objects · Domain Services · Aggregates │
├─────────────────────────────────────────────────────────┤
│  基础设施层 Infrastructure                               │
│  WASM Bridge · Data Repo · Logger · Persistence          │
└─────────────────────────────────────────────────────────┘
```

### 3.2 表现层（Presentation）

**职责**：渲染可视化、接收用户输入、展示 UI。

**组成**：

- `pages/`：Next.js 路由页面（首版仅一个主场景页）。
- `components/`：React 组件（搜索框、详情面板、维度调节器）。
- `scene/`：Three.js 场景封装（相机、光源、节点、气流、气团）。
- `hooks/`：React Hooks（`useGalaxy`、`useNode`、`useSearch`）。
- `store/`：Zustand 状态（视图状态、焦点节点、筛选条件）。

**依赖规则**：仅依赖应用层接口，不直接调用基础设施层。

### 3.3 应用层（Application）

**职责**：编排用例、转换 DTO、调度领域服务与基础设施。

**组成**：

- `usecases/`：用例（`FocusNodeUseCase`、`SearchUseCase`、`AdjustDimensionUseCase`）。
- `dto/`：数据传输对象（与表现层交互的结构）。
- `ports/`：端口接口（定义所需的能力，由基础设施实现）。

**用例示例**：

```text
FocusNodeUseCase
  输入：节点ID
  流程：
    1. 调用 NodeRepository.findById 获取节点
    2. 调用 RelationService.findRelated 获取相关节点
    3. 调用 LayoutService.computeConvergence 计算汇聚位置
    4. 返回 ConvergenceResult DTO
  输出：ConvergenceResult
```

### 3.4 领域层（Domain）

**职责**：承载核心业务逻辑，与框架完全解耦。

**组成**：

- `entities/`：实体（`Poet`、`Work`、`Dynasty`）。
- `value-objects/`：值对象（`TalentScore`、`PopularityScore`、`LuckScore`、`ThreeQi`）。
- `aggregates/`：聚合根（`Galaxy`、`PoetAggregate`）。
- `services/`：领域服务（`ScoringService`、`RelationService`、`LayoutService`）。
- `events/`：领域事件（`NodeFocused`、`DimensionAdjusted`）。

**特征**：

- 纯 TypeScript 实现（不依赖 React、Three.js、WASM）。
- 可独立单元测试。
- 通过端口接口与外界通信。

> 详细模型设计见 [04-领域模型设计](./04-领域模型设计.md)。

### 3.5 基础设施层（Infrastructure）

**职责**：实现端口接口，提供技术能力。

**组成**：

- `wasm/`：Rust WASM 桥接（检索、bincode 编解码、评分/聚类备选）。
- `persistence/`：数据持久化（IndexedDB 缓存）。
- `data/`：数据加载（JSON 数据集、空间索引数据加载）。
- `logging/`：日志系统（详见第 6 章）。
- `i18n/`：国际化资源（首版仅中文）。

### 4.2 模块依赖规则

```
presentation ──► application ──► domain ◄── infrastructure
                                    ▲

```

**强制约束**：

- `domain` 不依赖任何其他层。
- `application` 仅依赖 `domain` 的端口接口。

- `presentation` 依赖 `application` 的用例与 DTO，不直接依赖 `infrastructure`。

依赖通过依赖注入（DI）在组合根（`presentation` 的入口）完成装配。

## 5. 数据流

### 5.1 启动数据流

```
1. 浏览器加载 Next.js 静态页面
2. 表现层触发 InitializeUseCase
3. CompositionRoot.initialize() → WasmBridge.init()（WASM 模块初始化）
4. 应用层调用 DataRepository.load
5. 基础设施层加载 JSON 数据集（poets.json / works.json / nodes.json / scores.json）
6. 应用层调用 LayoutService.computeInitialLayout
7. 表现层接收 GalaxyDTO，渲染星系
8. WasmBridge 首次 queryNearby 时惰性加载 spatial-index.json，构建 JS KD-Tree
```

### 5.2 聚气交互数据流

```
1. 用户点击节点 → 表现层触发 FocusNodeUseCase
2. 应用层调用 NodeRepository.findById
3. 应用层调用 RelationService.findRelated（WASM 加速）
4. 应用层调用 LayoutService.computeConvergence
5. 应用层返回 ConvergenceResult DTO
6. 表现层启动聚气动画（Three.js）
7. 动画完成，展示详情面板
```

### 5.3 搜索数据流

```
1. 用户输入查询 → 表现层触发 SearchUseCase
2. 应用层调用 SearchPort.search（WASM 倒排索引）
3. WASM 返回匹配节点 ID 列表
4. 应用层调用 NodeRepository.findByIds 批量获取
5. 应用层返回 SearchResultDTO
6. 表现层渲染结果列表
7. 用户点击结果 → 触发 FocusNodeUseCase（同 5.2）
```

## 6. 日志系统

### 6.1 日志级别

| 级别 | 标识 | 用途 |
| --- | --- | --- |
| DEBUG | `DEBUG` | 调试信息（开发期开启） |
| INFO | `INFO` | 关键操作行为与结果（默认级别） |
| ERROR | `ERROR` | 错误信息（含堆栈） |

### 6.2 日志格式

```
[YYYY-MM-DD HH:MM:SS.SSS] [级别] [线程ID|进程ID] [模块:行号] - 日志内容
```

**示例**：

```
[2026-06-23 14:30:15.123] [INFO] [1|1024] [WasmBridge:42] - WASM 模块初始化完成，耗时 312ms
[2026-06-23 14:30:16.456] [ERROR] [1|1024] [DataRepository:88] - 数据加载失败：数据集版本不匹配
```

### 6.3 输出与轮转

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 终端输出 | 开启 | 开发环境控制台 |
| 文件输出 | 开启 | 生产环境 |
| 文件路径 | `logs/` | 相对应用根目录 |
| 文件命名 | `wenqi-YYYYMMDD.log` | 如 `wenqi-20260623.log` |
| 轮转策略 | 按日期 | 每日一个文件 |
| 保留天数 | 32 天 | 自动清理过期日志 |
| 时间戳 | 本地时间 | 不含时区，格式 `YYYY-MM-DD HH:MM:SS.SSS` |

### 6.4 脱敏策略（强制）

**禁止记录**：

- 密码、口令、令牌。
- 完整身份证号（如需记录须脱敏为 `110101********1234`）。
- 手机号（如需记录须脱敏为 `138****5678`）。
- 邮箱（如需记录须脱敏为 `z***@example.com`）。
- 任何用户输入的敏感文本。

**实现要求**：

- 日志门面提供 `sanitize()` 工具函数，所有外部输入入库前必须经过脱敏。
- 代码审查清单包含「日志脱敏检查」项。

### 6.5 日志内容规范

- 统一使用**中文**。
- 记录**操作行为**（如「加载节点数据」）、**执行结果**（如「成功，共 5000 条」）、**错误信息**（如「失败：数据集版本不匹配」）。
- 便于问题排查与审计。

### 6.6 模块化日志

各模块通过命名空间区分：

| 模块 | 命名空间 |
| --- | --- |
| WASM 桥接 | `WasmBridge` |
| 数据仓储 | `DataRepository` |
| 渲染引擎 | `SceneRenderer` |
| 应用用例 | `UseCase.*` |
| 领域服务 | `Domain.*` |
| 日志系统 | `Logger` |

### 6.7 浏览器环境实现策略

日志持久化在浏览器环境中使用 IndexedDB 实现（详见 [06-持久化设计文档](./06-持久化设计文档.md)）：

- 日志写入 IndexedDB `logs` 对象存储，按 `timestamp` 索引。
- 启动时调用 `rotate(32)`，清理超过 32 天的记录。
- 提供"导出日志"功能，按日期范围生成 `wenqi-YYYYMMDD.log` 文件下载。
- 控制台同步输出（开发环境）。

## 10. 安全设计

### 10.1 客户端安全

- CSP（内容安全策略）严格限制脚本来源。
- WASM 模块完整性校验（SRI）。
- 数据集完整性校验（哈希）。
- 禁用 `eval`、内联脚本。

### 10.2 数据安全

- 仅使用开源协议数据集，记录来源与协议。
- 数据加工脚本可追溯，每次更新生成变更日志。
- 用户视图配置仅存本地，不上传。

### 10.3 日志安全

- 严格遵循脱敏策略（见 6.4）。
- 生产环境默认 INFO 级别，不输出 DEBUG。
- 日志文件访问权限受限。

## 11. 性能优化策略

### 11.1 渲染优化

- **实例化渲染**：节点使用 `InstancedMesh`，单次 draw call 渲染上万个。
- **LOD 分级**：根据相机距离切换节点密度。
- **视锥剔除**：仅渲染视野内节点。
- **气流着色器**：自定义 Shader，GPU 加速光粒流动。
- **离屏 Canvas**：详情面板与场景分离，避免重绘。

### 11.2 计算优化

- **WASM 加速**：评分、索引、检索下沉至 Rust。
- **共享内存**：高频数据通过 `SharedArrayBuffer` 零拷贝传递。
- **Web Worker**：耗时计算放入 Worker，避免阻塞主线程。
- **增量更新**：维度调节时仅重算受影响节点。

### 11.3 渲染引擎降级策略

为确保 WebGL 不可用时的用户体验，实现三层渲染引擎：

```
检测 WebGL 2.0 → 失败 → 检测 WebGL 1.0 → 失败 → 降级模式
     │                    │                      │
     ▼                    ▼                      ▼
  ThreeSceneEngine     Canvas2DEngine         TextFallbackEngine
  (3D 星系)            (2D 平面星系)          (文字列表)
```

- **ThreeSceneEngine**（主方案）：完整 3D 星系，WebGL 2.0。
- **Canvas2DEngine**（降级方案）：放弃 Z 轴与三维旋转，用 Canvas 2D 渲染平面化星系，保留节点呼吸与聚气/散气逻辑。
- **TextFallbackEngine**（兜底方案）：静态页面，诗人列表 + 搜索 + 作品详情，保留「文气」视觉风格。

三引擎实现同一 `RenderEngine` 接口，在 `InitializeUseCase` 中根据 WebGL 检测结果注入。应用层与领域层完全不受渲染引擎影响。

### 11.4 加载优化

- **代码分割**：Next.js 动态导入，首屏仅加载核心模块。
- **数据分片**：大数据集按朝代/体裁分片，按需加载。
- **字体子集化**：仅包含实际使用的字符。
- **预加载**：关键资源 `<link rel="preload">`。

### 11.5 性能监控方案

为度量和保障性能指标，建立分层监控体系：

#### 11.5.1 监控指标

| 指标 | 目标值 | 采集方式 | 告警阈值 |
| --- | --- | --- | --- |
| 首屏加载时间 | 桌面 ≤3s，移动 ≤5s | Performance API + 自定义埋点 | >5s |
| WASM 初始化时间 | <500ms | 自定义计时 | >1s |
| 渲染帧率 | 桌面 60fps，移动 30fps | requestAnimationFrame 计数 | <24fps |
| 搜索响应时间 | <200ms | 自定义计时 | >500ms |
| 聚气动画帧率 | ≥30fps | requestAnimationFrame 计数 | <24fps |
| 内存使用 | <200MB | performance.memory | >300MB |

#### 11.5.2 采集实现

```typescript
// 基础设施层：性能监控端口
interface PerformanceMonitor {
  // 记录指标
  record(metric: MetricName, value: number, tags?: Record<string, string>): void;

  // 启动帧率监控
  startFpsMonitor(intervalMs?: number): void;

  // 获取性能报告
  getReport(): PerformanceReport;

  // 导出指标（开发环境）
  export(): Promise<Blob>;
}

type MetricName =
  | 'page.load'           // 首屏加载
  | 'wasm.init'           // WASM 初始化
  | 'wasm.call'           // WASM 调用耗时
  | 'render.frame'        // 渲染帧时间
  | 'search.response'     // 搜索响应
  | 'convergence.frame'   // 聚气动画帧
  | 'memory.usage';       // 内存使用

interface PerformanceReport {
  readonly metrics: Array<{
    name: MetricName;
    avg: number;
    p50: number;
    p95: number;
    p99: number;
    count: number;
  }>;
  readonly generatedAt: string;
}
```

#### 11.5.3 采集策略

| 场景 | 采集频率 | 说明 |
| --- | --- | --- |
| 首屏加载 | 每次 | 必采 |
| WASM 调用 | 每次 | 必采 |
| 渲染帧率 | 采样 10% | 避免监控本身影响性能 |
| 搜索响应 | 每次 | 必采 |
| 内存使用 | 每 30s | 定时采集 |

#### 11.5.4 开发环境工具

- **Performance 面板**：浏览器 DevTools Performance 标签页。
- **自定义 HUD**：开发模式下显示实时帧率、WASM 调用次数、内存使用。
- **日志输出**：性能指标以 `[PERF]` 前缀输出至控制台。

#### 11.5.5 生产环境策略

- 性能指标仅记录至本地日志，不上传。
- 性能告警通过日志 ERROR 级别触发，便于排查。

## 12. 错误处理

### 12.1 错误分层

| 层 | 错误类型 | 处理策略 |
| --- | --- | --- |
| 领域层 | 领域异常（如无效评分） | 抛出领域异常，由应用层捕获 |
| 应用层 | 用例异常 | 转换为用户可读错误，记录日志 |
| 基础设施层 | 技术异常（如 WASM 加载失败） | 降级处理 + 日志 + 用户提示 |
| 表现层 | UI 异常 | 错误边界捕获，展示兜底 UI |

### 12.2 错误信息规范

- 所有面向用户的错误信息**统一中文**。
- 错误信息须**可操作**（如「数据加载失败，请刷新重试」）。
- 技术细节记录日志，不直接展示给用户。
- 错误码体系详见 [05-API接口设计文档](./05-API接口设计文档.md)。

### 12.3 错误恢复与重试策略

针对关键操作的错误，定义分级恢复策略：

#### 12.3.1 WASM 模块加载失败

| 阶段 | 策略 | 说明 |
| --- | --- | --- |
| 首次加载失败 | 自动重试 2 次，间隔 1s | 网络抖动场景 |
| 重试失败 | 降级至 Canvas 2D 引擎 | 放弃 3D 渲染，保留核心功能 |
| 完全不可用 | 展示文字兜底页面 | 引导用户检查网络或更换浏览器 |

#### 12.3.2 数据集加载失败

| 阶段 | 策略 | 说明 |
| --- | --- | --- |
| 网络加载失败 | 自动重试 3 次，间隔 2s | 网络不稳定 |
| 重试失败 | 尝试加载 IndexedDB 缓存 | 离线场景 |
| 缓存不可用 | 展示错误页面，引导刷新 | 数据完全不可用 |

#### 12.3.3 WASM 初始化超时

| 阶段 | 策略 | 说明 |
| --- | --- | --- |
| 超时（>5s） | 展示加载进度，继续等待 | 低端设备 |
| 超时（>15s） | 提示用户，提供「跳过」选项 | 降级至纯前端计算 |
| 用户选择跳过 | 禁用 WASM 加速功能 | 搜索、聚类等功能降级 |

#### 12.3.4 IndexedDB 写入失败

| 阶段 | 策略 | 说明 |
| --- | --- | --- |
| 配额超限 | 按优先级清理旧数据 | 日志 > 旧评分 > 旧索引 > 数据集 |
| 清理后仍失败 | 降级至内存缓存 | 本次会话可用，刷新后丢失 |
| 浏览器不支持 | 降级至 localStorage | 仅存储视图配置 |

#### 12.3.5 重试策略配置

在 `application.yml` 中统一配置：

```yaml
error:
  retry:
    wasm:
      maxAttempts: 2
      intervalMs: 1000
    data:
      maxAttempts: 3
      intervalMs: 2000
    wasmInit:
      timeoutMs: 5000
      warnTimeoutMs: 15000
```

#### 12.3.6 错误恢复原则

1. **渐进降级**：优先保证核心功能可用，高级功能按优先级降级。
2. **用户可控**：超时场景提供「跳过」或「重试」选项，不强制等待。
3. **状态可恢复**：降级后功能在条件满足时自动恢复（如网络恢复后重新加载）。
4. **日志完整**：所有降级与恢复操作须记录日志（中文，脱敏）。
