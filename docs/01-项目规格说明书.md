## 1. 项目概述

### 1.1 项目缘起

「文气」一词源自曹丕《典论·论文》：「文以气为主，气之清浊有体，不可力强而致。」古典文学批评自古即以「气」论文章高下、品性风骨。本项目将这一传统美学概念数字化、空间化，构建一座可漫游、可凝视、可呼吸的「古典文学星系」。

### 1.2 核心理念

**文脉如气，流动不居。**

- **知识本体即「气」**：每颗星（知识节点）并非静止数据点，而是带有呼吸动画的「气点」——脉动、闪烁，如活体宇宙。
- **知识关联即「气流」**：节点之间的边不再是僵硬线条，而是流动光粒或氤氲雾带，模拟「气」在文脉中的流转。
- **知识星云即「气团」**：缩放视角后，整片「文气」弥漫成星云，不同朝代、体裁的气团呈现不同色彩与密度。

### 1.3 项目定位

纯客户端、离线可用的沉浸式古典文学知识探索应用。以三维星系可视化为载体，以「文气」流动为美学语言，将诗人、作品、朝代、体裁之间的关系编织为一片可交互的知识星云。

### 1.4 目标用户

| 画像 | 特征 | 关键体验 |
|------|------|---------|
| 古典文学爱好者「云观」 | 有兴趣但缺系统认知 | 视觉震撼 + 低门槛 + 即开即用 |
| 文学研究者「砚秋」 | 需多维分析、关注关系脉络 | 数据可信 + 维度可调 + 关系可溯 |
| 教育工作者「师竹」 | 需课堂演示文学脉络 | 演示流畅 + 筛选灵活 + 中文友好 |
| 美学探索者「青衫」 | 关注可视化与东方美学 | 画面精致 + 动效流畅 + 可分享 |

### 1.5 价值主张

| 维度 | 传统文学数据库 | 文气（WenQi） |
|------|--------------|--------------|
| 知识形态 | 静态表格、列表 | 流动星系、活体宇宙 |
| 探索方式 | 检索—阅读 | 凝视—扰动—汇聚 |
| 美学表达 | 文字为主 | 三维空间 + 韵律 + 节奏 |
| 关系呈现 | 显式链接 | 气流光粒、雾带 |
| 用户感受 | 信息获取 | 沉浸观气 |

## 2. 项目范围

### 2.1 包含范围

| 维度 | 内容 |
|------|------|
| 数据范围 | 先秦至近现代 ≥2000 位诗人、≥50000 首作品 |
| 体裁覆盖 | 诗、词、曲、赋、文、小说 |
| 功能范围 | 星系可视化、节点呼吸与气流、聚气/散气交互、三气坐标轴、朝代/体裁气团、搜索定位、详情面板、维度调节、分享截图 |
| 平台范围 | 桌面端 Chrome/Edge/Firefox/Safari，移动端 iOS Safari/Android Chrome |

### 2.2 不包含范围（首版）

| 项目 | 说明 |
|------|------|
| 用户账号系统 | 无登录/注册，配置仅存 localStorage |
| 后端服务 | 无 HTTP 服务器，纯静态分发 |
| 用户贡献 | 不支持上传或编辑数据 |
| 第三方 API | 不依赖外部在线服务 |
| 实时协作 | 不支持多用户协同 |
| 移动端原生 App | 仅 PWA 支持，不打包为原生应用 |

### 2.3 交付形态

```
静态 CDN 分发（Vercel / Netlify）
  └── 浏览器内运行（离线可用）
       ├── Next.js 静态导出 SPA
       ├── Rust WASM 计算模块
       └── 预加工 JSON 数据集
```

## 3. 技术架构总览

### 3.1 四层 DDD 架构

```
┌──────────────────────────────────────────┐
│  表现层（Presentation）                    │
│  React + Three.js + Zustand              │
├──────────────────────────────────────────┤
│  应用层（Application）                     │
│  UseCases + DTO + 事件编排                │
├──────────────────────────────────────────┤
│  领域层（Domain）                          │
│  实体 + 值对象 + 领域服务 + 聚合根         │
├──────────────────────────────────────────┤
│  基础设施层（Infrastructure）              │
│  WASM 桥接 + 数据仓储 + 日志 + 持久化      │
└──────────────────────────────────────────┘
```

### 3.2 技术栈

| 层次 | 技术 | 版本 |
|------|------|------|
| 计算层 | Rust → WASM | stable |
| 构建工具 | bun | ≥ 1.0 |
| 语言 | TypeScript | ≥ 5.0 |
| 框架 | Next.js | ≥ 16 |
| UI | React | ≥ 19.2 |
| 3D 渲染 | Three.js | ≥ 0.170 |
| 状态管理 | Zustand | ≥ 4 |
| 测试 | Vitest + wasm-bindgen-test | — |
| 样式 | Tailwind CSS | ≥ 3 |
| 字体 | Noto Sans SC（SIL 协议） | — |
| 配置 | application.yml | — |

### 3.3 Rust / TypeScript 边界

| Rust 负责（计算密集） | TypeScript 负责（交互与渲染） |
|---------------------|---------------------------|
| 三气评分算法（离线数据加工调用） | Three.js 场景管理 |
| 全文检索（倒排索引 + 双通道降级） | React 组件与 UI 状态 |
| 通用 bincode 编解码器 | 用户交互事件处理 |
| 聚类算法（WASM 备选，默认 JS 端） | 空间索引（JS KD-Tree，从 JSON 数据构建） |
| — | 节点布局计算（LayoutService 领域服务） |
| — | 动画缓动与时间轴 |
| — | 降级渲染引擎选择 |

### 3.4 WASM 通信策略

| 调用频率 | 数据格式 | 接口 |
|---------|---------|------|
| 低频（初始化、检索） | JSON（默认通道） | `SearchEngine.search`、`SearchEngine.buildIndex` |
| 中频（搜索） | bincode 优先，JSON 降级（双通道自动降级） | `SearchEngine.searchBinary` → 失败 → `SearchEngine.search` |
| 通用编解码 | bincode（不透明 String 中转） | `bincodeEncode` / `bincodeDecode`（`codec.rs`） |

## 4. 项目约束

### 4.1 性能指标

| 指标 | 桌面端 | 移动端 |
|------|--------|--------|
| 首屏加载（含字体） | ≤ 3s | ≤ 5s |
| 节点渲染帧率 | 60fps | 30fps |
| 散气模式帧率 | 45fps | 30fps |
| 搜索响应 | < 200ms | < 300ms |
| WASM 初始化 | < 500ms | < 800ms |
| 包体积（JS+WASM gzip） | ≤ 800KB | — |

### 4.2 兼容性

- 桌面：Chrome ≥ 90、Edge ≥ 90、Firefox ≥ 88、Safari ≥ 14
- 移动：iOS Safari ≥ 14、Android Chrome ≥ 90
- WebGL 2.0 优先，降级路径：WebGL 1.0 → Canvas 2D → 文字兜底
- 尊重 `prefers-reduced-motion`，关闭呼吸与气流动画

### 4.3 安全与隐私

- 无账号系统，不收集个人信息
- 视图配置仅存 localStorage
- 分享链接不含用户身份数据
- 日志严格脱敏（密码、身份证号、手机号、邮箱禁止明文记录）

### 4.4 语言与本地化

- 首版仅简体中文
- 文案与数据分离，预留 i18n 接口
- 界面上标明代朝气团色仅为视觉参考，评分「仅供参考」

## 5. 文档体系

本项目文档按编号组织，每份文档独立聚焦一个维度：

| 编号 | 文档 | 定位 |
|------|------|------|
| 01 | 项目规格说明书 | **总纲**：项目全局定义、范围、约束、技术栈总览 |
| 02 | 产品需求文档 PRD | **需求**：用户画像、功能需求、非功能需求、里程碑 |
| 03 | 架构设计文档 | **架构**：DDD 分层、模块划分、数据流、部署 |
| 04 | 领域模型设计 | **领域**：值对象、实体、聚合根、领域服务、仓储接口 |
| 05 | API 接口设计 | **接口**：用例接口、WASM 接口、数据契约、DTO、错误码 |
| 06 | 持久化设计文档 | **持久化**：跨环境存储、版本契约、数据分片、日志、迁移 |
| 07 | 诗云算法架构研究 | **研究**：参考项目算法剖析、性能工程、数据接缝设计 |
| 08 | 测试策略文档 | **测试**：分层测试策略、覆盖率要求、脚本配置、关键场景 |

**文档依赖关系**：

```
01 总纲
  ├── 02 需求（定义要做什么）
  ├── 03 架构（定义怎么做）
  ├── 04 领域模型（定义业务逻辑）
  ├── 05 API 接口（定义交互契约）
  ├── 06 持久化（定义数据存储）
  ├── 07 诗云研究（参考项目分析）

```

## 7. 术语表

| 术语 | 含义 |
|------|------|
| 文气 | 项目核心隐喻，文脉的流动之气 |
| 三气 | 才气（Y 轴）+ 人气（Z 轴）+ 运气（X 轴）的合称 |
| 才气 | 作品创造力、独特性评分 |
| 人气 | 影响力、被引用次数、知名度 |
| 运气 | 时间轴上的偶然性与历史机遇 |
| 聚气 | 点击节点触发相关节点向其汇聚的交互 |
| 散气 | 缩放拉远后节点聚合为气团的交互 |
| 气团 | 散气模式下同朝代/体裁节点的聚合视觉 |
| 气流 | 节点间边的光粒流动效果 |
| 气点 | 单个知识节点的拟人化称呼 |
| 星系 | 全部节点的三维空间集合 |
| 诗人 | 古典文学作者 |
| 作品 | 诗、词、曲、赋、文等具体作品 |
| 朝代 | 历史朝代（先秦至近现代） |
| 体裁 | 文学体裁（诗、词、曲、赋、文、小说） |
| 关联 | 节点间的关系（同朝代、同流派、引用等） |
